# Чек-лист проверки выгруженного проекта

По этому списку я разбираю выгрузку из Claude Design. Он же годится вам, если
захотите посмотреть сами. Порядок не случаен: механика сначала, потому что на
рваном документе искать смысл бессмысленно.

## 1. Механика (автоматически, `tools/check_design_export.py`)

- Все части от 1 до N на месте, ни одна не потеряна и не задвоена.
- Каждая часть открыта и закрыта своими маркерами.
- Набор разделов совпадает с манифестом: номера, названия, распределение по частям.
- Ни одной заглушки: `...`, `TODO`, «и так далее», «см. выше», «аналогично».
- Блок самопроверки на месте, числа в нём сходятся с фактически выданным.

## 2. Инварианты

Двенадцать инвариантов из `CLAUDE.md` — не пожелания, а условия, при нарушении
которых эксперимент портится молча. По каждому смотрю не «упомянут ли», а
«есть ли в архитектуре место, где он ломается»:

- **Журнал только дозаписывается.** Ищу любую операцию, которая правит запись
  задним числом: пересчёт `t_world`, «уточнение» действия после факта,
  дедупликацию на месте. Всё это должно быть отдельным производным слоем.
- **Три часов и хеш профиля в каждой записи.** Проверяю, что схема записи их
  содержит, и что `t_content = null` — законное значение, а не признак ошибки.
- **Мир не на паузе.** Ищу блокирующие вызовы в основном цикле: ожидание
  ответа большой модели, синхронный дисковый сброс, «дождаться конца навыка».
  Планировщик обязан отдавать лучший ответ на текущий момент по запросу.
- **Агент не получает координат, названий, разметки, счёта.** Проверяю каждый
  канал, включая неочевидные: имя окна, заголовок вкладки, метаданные файла,
  подписи в отладочном оверлее, имена ключей в структурах восприятия.
- **Текст хешируется до планировщика.** Смотрю, где именно стоит хеширование, и
  не проходит ли текст мимо — например, вместе с описанием сцены от большой
  модели, которая честно перепишет надпись словами.
- **Файрвол восприятия.** Самое хрупкое место. Большая модель отвечает «что я
  вижу». Проверяю, что в её ответе нет ни рекомендаций, ни оценок полезности,
  ни слов вида «опасно», «нужно», «следует» — иначе это «что делать» под видом
  описания. Отдельно смотрю, что предложения действий рождаются в другом
  механизме и не берут текст ответа как подсказку.
- **У каждого убеждения есть происхождение.** `hunch | testimony | experience`,
  `mu`, `sigma`, `n`, ссылка на эпизод. Ищу пути, по которым в хранилище
  попадает утверждение без происхождения.
- **Действие — это `(key, duration_ms, modifiers)`.** Ищу места, где действие
  превращается в дискретное событие: «нажать W» вместо «W на 340 мс».
- **Обратимость вместо списка запретов.** Осторожность выводится из «я не умею
  это откатить». Ищу захардкоженные чёрные списки — они означают подсказку.
- **Самоотчёты ни на что не влияют.** Ищу любую петлю, где слова агента о себе
  меняют его параметры, награду или память. Это необратимая порча эксперимента:
  один раз завязали — и уже не отличить обучение от отчёта об обучении.
- **Структурные переключатели форкают журнал.** Проверяю, что деление на
  `parameters` и `structural` проведено по каждому полю, а не объявлено вообще.
- **Отладочный канал отделён.** Ищу общий модуль, общий объект, общий путь —
  что угодно, через что агентский код может дотянуться до истинных координат.

## 3. Доменная независимость

- Есть ли решение, которое работает только в Minecraft (или только в шутере,
  или только в браузере)? Каждое такое место — либо ошибка, либо должно быть
  честно помечено как временная заглушка вехи.
- Есть ли числа, взятые из конкретной игры: пороги яркости, размеры инвентаря,
  типовые задержки? Они обязаны жить в `Profile`, а не в логике.
- Проверка на подсказку: если убрать из документа слово «Minecraft», перестанет
  ли что-нибудь быть понятным? Если да — там протекло знание о домене.

## 4. Полнота для перехода к коду

- Каждая структура данных описана полем за полем, с единицами измерения.
- У каждого модуля есть критерий готовности, проверяемый офлайн на записи, без
  запуска игры.
- Понятно, что источник истины, что производное, что пересобирается из журнала.
- Понятно, что делать при отказе: пропали кадры, игра свернулась, звук
  рассинхронизировался, большая модель не ответила.
- Ни одной «молчаливой заглушки»: функции, которая вернёт правдоподобное
  значение вместо реального. По правилам проекта это худшее, что может быть —
  такая функция ломает эксперимент незаметно.

## 5. Согласованность с уже зафиксированным

- Расхождения с `CLAUDE.md` — по каждому решаем осознанно, а не правкой на ходу.
- Расхождения с `MILESTONE-0-HARNESS.md` — особенно попытки затащить в веху 0
  то, чего там быть не должно: модели, планировщик, карточки сущностей, лепет.
- Новые термины — либо в таблицу словаря, либо убрать. Терминов-дублей быть
  не должно: один смысл — одно имя.
