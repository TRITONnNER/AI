# Харнесс вехи 0: как он устроен и что в нём замерено

Веха 0 — инфраструктура записи и воспроизведения опыта. Ни одной модели, ни
планировщика, ни карточек сущностей. Критерии готовности — в
`MILESTONE-0-HARNESS.md`; здесь то, как они выполнены, чего они стоили и что
осталось непроверенным.

## Как запустить

```bash
pip install -e '.[dev]'          # или просто: pip install numpy pytest
python -m pytest -q              # 107 тестов, около 5 секунд

python -m harness.cli backends                  # что доступно на этой машине
python -m harness.cli profile                   # профиль вехи 0 и оба хеша
python -m harness.cli gen-corpus /tmp/sess      # синтетическая сессия
python -m harness.cli verify /tmp/sess          # целостность записи
python -m harness.cli replay /tmp/sess          # покадрово
python -m harness.cli selfworld /tmp/sess       # разделение слоёв (0.6)
```

Без установки пакета работает `PYTHONPATH=src python -m harness.cli ...`.

## Раскладка

```
src/harness/
  core/        часы, профиль, действие, символы, журнал, хранилище блоков
  capture/     источники кадров и звука
  inject/      инъекция ввода, маска, СТОП, сторожевой таймер
  vision/      разделение экранного и мирового слоёв (0.6)
  corpus/      генератор синтетического корпуса
  agentside/   то, и только то, что доступно агенту
  debug/       поток исследователя: истина, координаты, расшифровка, раскладка
  session.py   запись и чтение сессии
  cli.py       командная строка
```

Границу между `agentside` и `debug` держит не дисциплина, а граф импортов:
`tests/test_invariants.py::test_invariant_12_agentside_cannot_reach_debug`
обходит импорты транзитивно и падает, если путь появился хоть через десять
посредников. То же для `harness.inject`.

Чтобы граница держалась, устройственный backend не импортирует таблицу
скан-кодов, а получает односторонний резолвер:

```python
km = Keymap.linux_evdev()                 # живёт в harness.debug
device = UinputDevice(resolve=km.resolver())   # получает только функцию
```

Резолвер переводит непрозрачный выход в скан-код и не умеет обратно: ни
перечислить таблицу, ни узнать имя клавиши через него нельзя.

## Решения и разрешённые противоречия

### Два хеша профиля, а не один

`CLAUDE.md` требует штамповать «хеш профиля» в каждую запись. `MILESTONE-0`, 0.5,
требует, чтобы по хешу можно было отфильтровать журнал и получить **совместимые**
записи. С одним хешем это несовместимо: параметры разрешено крутить на ходу, и
если хеш считается и по ним, то каждый поворот ручки делает предыдущие записи
«несовместимыми», хотя ветка та же.

Поэтому штампуются оба:

- `structure_hash` — только по `structural`. Определяет ветку и совместимость.
- `profile_hash` — по `structural` и `parameters`. Точная настройка записи.

Инвариант 2 не нарушен: требуемый хеш профиля на месте, второй добавлен рядом.
Фильтр совместимости (`Journal.compatible()`) смотрит на `structure_hash`.

### Заглушённая маской попытка пишется в журнал

В дизайне пульта сказано: заблокированная клавиша «в журнал не попадает, поэтому
карта тела не загрязняется мёртвыми выходами». Это ломает инвариант 1. Агент
решил нажать, драйвер молча съел, агент завёл убеждение «выход молчит» — а
причины этого убеждения в журнале нет, и пересборка убеждений из журнала даст
другую карту тела, чем та, по которой агент жил.

Здесь попытка пишется всегда, с `masked=True` и причиной (`mask:window:OUT_2C`).
Что забыть при пересборке — решает слой убеждений; из источника истины не
вырезается ничего. Проверяется
`test_milestone.py::test_0_2_masked_attempt_is_journaled`.

### Маска говорит на языке выходов, не клавиш

В пульте маска индексирована истинными именами (`Q`, `F5`, `Alt`). Здесь
`InputMask` принимает только непрозрачные идентификаторы и отказывается от `F5`
с объяснением. Исследователь задаёт маску настоящими именами через
`Keymap.output_for_key`, но сама маска настоящих имён не хранит и выдать не
может.

### Цепочка хешей вместо обещания дозаписи

«Журнал только дозаписывается» — заявление, которое ничего не стоит, пока его
нельзя проверить. Каждая запись несёт хеш от своего содержимого и хеша
предыдущей. Правка, вставка и удаление строки рвут цепочку, `verify()` называет
номер записи. Файлы открываются в режиме `"a"`; функции «переписать запись» в
модуле нет.

### Незнание обратимости — это максимальная осторожность

`Reversibility` с `n == 0` не может нести правдоподобные `mu`/`sigma`:
конструктор это запрещает, чтобы незнание не выглядело как знание.
`caution` при `n == 0` равна 1.0. Никакого списка запретных выходов в коде нет —
тест `test_invariant_9_no_forbidden_list_anywhere` ищет и падает, если появится.

### Действие невыразимо без длительности

`Action.key(output, 0)` — ошибка: «удержание 0 мс — это дискретное событие,
которого в модели нет». Строка `Action.key("W", 100)` тоже ошибка: имя клавиши
не проходит проверку формата выхода.

### Три часов, и ни одних настенных

`Stamp` несёт `t_self`, `t_world`, `t_content`. Настенное время есть на объекте
кадра (`monotonic_ns`) и используется только для диагностики пропусков и
рассинхрона — в журнал как часы не попадает. Сравнивать записи по настенным
часам бессмысленно: скорость мира и скорость агента меняются независимо.

### СТОП нарезает удержание, а не ждёт его конца

Удержание 340 мс — не `sleep(0.34)`. Между нажатием и отпусканием сон идёт
срезами по 5 мс, и после каждого спрашивается СТОП. Поэтому зажатый выход
отпускается не позже одного среза после стопа, а освобождение стоит в `finally`
— то есть случается даже когда выше по стеку всё рухнуло. При кадре 33 мс это
шесть срезов запаса. Замерено тестом по числу вызовов сна, а не по стенным
часам: тест не должен зависеть от загрузки машины.

## Замеры

Все числа сняты на синтетическом корпусе 320×180, 96 кадров, сид 1, на этой
машине. Воспроизводятся командами выше.

### Сколько занимает запись

| Способ | На кадр | Час 1080p 30 к/с |
|---|---|---|
| Без сжатия | 56.2 КиБ | 195 ГиБ |
| zlib покадрово | 49.8 КиБ | 185 ГиБ |
| Опорный кадр + разность (как сейчас) | 28.5 КиБ | 106 ГиБ |

Разбивка по типу кадра объясняет, откуда средняя величина:

| Кадр | Медиана на диске |
|---|---|
| Экран не менялся | **0.1 КиБ** |
| Камера панорамирует | 45.3 КиБ |

Разностное кодирование делает неподвижный экран практически бесплатным — в 450
раз дешевле. Именно это и есть основной режим настоящей работы: меню, стояние на
месте, чтение, браузер. При непрерывном панорамировании разность не помогает, и
здесь честный ответ такой: **шардовое хранилище не выполняет критерий 0.3 для
живой записи 1080p**. Для неё нужен видеокодек, как и предполагает `CLAUDE.md`
(«кадры отдельным хранилищем — видеопоток или шарды»).

Кодек не реализован потому, что на этой машине нет `ffmpeg`, а непроверенный
кодек в хранилище опыта опаснее отсутствующего: он испортит корпус незаметно.
Шардовое хранилище остаётся для корпусов, тестов и записи небольших сессий, и
его предел теперь измерен, а не предполагается.

Отдельно: синтетическая текстура — шум вплоть до одного пикселя, то есть худший
случай для любого сжатия. На настоящих игровых кадрах панорама сожмётся лучше;
насколько — узнаем на первой живой записи.

### Промотка

| Операция | Время |
|---|---|
| Открыть последний кадр записи | 2.0 мс |
| Открыть произвольный кадр | 7.6 мс |
| Пройти всю запись (96 кадров) | 39 мс |

Критерий 0.3 «произвольный момент открывается за доли секунды» выполнен.
Цена промотки ограничена сверху `frame_keyframe_interval`: чтобы собрать любой
кадр, читается не больше 30 блоков.

### Разделение себя и мира (0.6)

Пять сидов, один и тот же профиль:

| Сид | IoU | Полнота | Точность |
|---|---|---|---|
| 0 | 0.746 | 0.987 | 0.753 |
| 1 | 0.750 | 0.988 | 0.757 |
| 2 | 0.746 | 0.989 | 0.752 |
| 3 | 0.735 | 0.987 | 0.742 |
| 11 | 0.745 | 0.987 | 0.753 |

Интерфейс находится практически целиком (пропущено 26–36 пикселей из 2768).
Ошибка — почти вся в другую сторону: около 880 пикселей мира принято за
интерфейс. Это ореол шириной в радиус окна поддержки вокруг границ интерфейса:
у пикселя мира, соседнего с неподвижной панелью, окно частично накрывает эту
панель. Уточнение границы (субпиксельный сдвиг, учёт краёв) — задача следующей
вехи; для критерия «стабильно выделяет область интерфейса» текущего хватает, и
разброс по сидам это подтверждает.

Путь к этим числам стоит записать, потому что оба тупика типичны:

1. **Сетка блоков 32 px — IoU 0.117.** Элементы интерфейса высотой 8–10 px, то
   есть мельче блока. Внутри блока смешаны оба слоя, мир побеждает голосованием.
2. **Скользящее окно 7 px попиксельно — IoU 0.638.** Смешивание ушло, появился
   ореол по границам.
3. **Согласие двух масштабов — IoU 0.750.** Голос идёт только там, где с окном
   согласен и сам пиксель: у пикселя интерфейса своя разность почти ноль, у
   пикселя мира при панораме — заметная. Ложных пикселей стало 880 вместо 1533.

Никакого перебора сдвигов в этом нет: глобальный сдвиг берётся фазовой
корреляцией через FFT (три преобразования вместо 2401 сравнения полного кадра
при радиусе поиска 24), а дальше проверяются ровно две гипотезы. OpenCV, который
`CLAUDE.md` предлагает для оптического потока, здесь не понадобился — `numpy.fft`
достаточно, и это на одну тяжёлую зависимость меньше.

Ещё две вещи выяснились позже, на кросс-доменном замере, и обе меняют не столько
метод, сколько представление о его границах:

- **Параллакса недостаточно.** Там, где кадр не смещается целиком — рабочий стол,
  проигрыватель, — параллакс обязан молчать, и молчит: 100 % нерешённых пикселей.
  Отказ честный, но бесполезный, поэтому рядом появился второй признак —
  неподвижность. Он слабее (не различает «прибито к экрану» и «стоит на месте»), и
  какой признак ответил, теперь называется явно. Подробности и числа — в
  `ARCHITECTURE-AGENT.md`, раздел «Доменная независимость».
- **Ослабление порога отброшено по замеру.** Голосовать за экранный слой не только
  при «пиксель не изменился», но и при «своя разность в несколько раз меньше» —
  выглядит разумно и роняет точность с 1.00 до 0.84 без прироста полноты.

### Фон и превышение над фоном

| Величина | Значение |
|---|---|
| Изменение кадра без действий | 0.0011 ± 0.0003 |
| Изменение кадра при действии | 0.598 ± 0.022 |
| Превышение | 1859 σ фона |

Такой контраст — свойство синтетики: цифровой захват без потерь даёт побитово
одинаковые неподвижные кадры, поэтому фон почти нулевой. На живой записи с
источника, сжатого с потерями, фон будет заметно выше; генератор умеет добавлять
шум по мировому слою (`generate_session(..., noise=N)`) именно для такой проверки.

## Синтетический корпус: что он есть и чего не заменяет

Корпус разрывает круг «модуль нельзя проверить без записи, а запись нельзя
получить без харнесса». Он даёт экранный слой, прибитый к экрану, и мировой,
который смещается при повороте камеры, — ровно то различие, которое ищет 0.6.
Истина (маска интерфейса, покадровый сдвиг камеры, пеленг звука, таблица
расшифровки) пишется в отладочный поток, поэтому проверяемый код её не видит.

Чего в нём нет: дрожания частоты кадров, разорванных кадров, сжатия с потерями,
настоящего рассинхрона звука, реакции игры на ввод. Сессия помечена
`synthetic: true`, и это не косметика: любой модуль, работающий на синтетике,
обязан быть перепроверен на первой живой записи.

Шум по умолчанию нулевой. Это не упрощение, а верная модель: захват экрана
цифровой и без потерь, неподвижная часть кадра побитово совпадает с предыдущим
кадром, сенсорного шума там нет. Добавлять его «для реалистичности» значило бы
врать про источник и заодно испортить замер объёма записи.

## Что не проверено

Список честный и предметный. Ни одна из этих вещей не подменена заглушкой,
возвращающей правдоподобное значение: все они отказываются работать с текстом,
из которого понятно, что сделать.

| Что | Почему не проверено | Что будет, если вызвать |
|---|---|---|
| Захват экрана через `mss` | в контейнере нет ни `DISPLAY`, ни `WAYLAND_DISPLAY` | `BackendUnavailable` с указанием, что поставить и где запускать |
| Захват на Windows (`dxcam`) | нужен Windows | `BackendUnavailable`: писать вслепую нельзя, непроверенный Desktop Duplication отдаёт устаревшие кадры незаметно |
| Захват на macOS (ScreenCaptureKit) | нужен macOS | то же |
| Петлевой звук (`sounddevice`) | нет звукового устройства | `BackendUnavailable`: обычный микрофон не подходит, нужен monitor-источник или WASAPI loopback |
| Инъекция через `uinput` | нет `/dev/uinput` и нет игры | `InjectionUnavailable` с командой `modprobe uinput` и указанием на права |
| Инъекция на Windows (`SendInput`) | нужен Windows и живая игра | `InjectionUnavailable`: проверять надо именно доставку скан-кода, виртуальные коды игры игнорируют |
| Горячая клавиша СТОПа | нужна графическая сессия | `NotImplementedError`. СТОП вызывается программно и через код — это работает; молча не слушать клавишу было бы хуже, исследователь решил бы, что аварийная остановка есть |
| Десять минут захвата без пропусков (0.1) | нужен живой источник | проверено то, что **обнаружение** пропуска и рассинхрона работает: `verify()` их находит и сообщает |
| Ввод, дошедший до настоящей игры (0.2) | нужна игра | проверена форма API, обрыв по СТОПу, сторожевой таймер и запись попыток |

## Что осталось сделать в вехе 0

1. **Видеокодек для кадров.** Предел шардового хранилища измерен: 106 ГиБ в час
   при 1080p с непрерывным движением. Нужен `ffmpeg` и проверка, что кодек не
   теряет кадры и не сдвигает их относительно журнала.
2. **Живая запись.** Первая сессия настоящей игры: она же проверит захват,
   инъекцию, звук и все три критерия, которые сейчас проверены только со стороны
   обнаружения отказов.
3. **Уточнение границы в 0.6.** Ореол в радиус окна — единственный источник
   ошибки; полнота уже 0.99.
4. **Экран корпуса.** Список записанных сессий, их целостность, прогон модуля по
   записи с сравнением с прошлым результатом. Сейчас это делается командами, но
   у главного ежедневного инструмента должен быть свой вид в пульте — это
   отмечено и в разборе пульта.

## Что сделано против дизайна пульта

`docs/DESIGN-REVIEW-CONSOLE.md` нашёл в пульте четыре нарушения инвариантов и три
вопроса. В коде исправлены:

- пункт 1 (маска не пишет в журнал) — попытка пишется всегда;
- пункт 3 (отладочный канал в одном объекте с агентским) — раздельные пакеты,
  проверка графом импортов;
- пункт 4 (маска на истинных именах клавиш) — маска только на выходах,
  соответствие живёт в `harness.debug` и передаётся односторонним резолвером;
- пункт 6 (вмешательства не учитываются) — `Recorder.record_intervention`
  пишет их отдельным видом записи, так что прогон с вмешательствами больше не
  выглядит чистым;
- пункт 7 (константы поведения в коде) — все настройки в `Profile`, тест
  проверяет, что параметры и структурные переключатели не пересекаются.

Пункт 2 (нет прибора на файрвол восприятия) в вехе 0 исправить нечем: большой
модели нет. Вместо вакуумно зелёного теста стоит растяжка
`test_invariant_6_tripwire_no_planner_without_firewall_instrument`: она падает в
тот момент, когда в дереве появляется планировщик или клиент модели, и требует
вместе с ним модуль `firewall`, записывающий сырой вопрос и сырой ответ.

Пункт 5 (внешнее влияние на цели за необратимой границей) — вопрос к дизайну, а
не к вехе 0: целей здесь ещё нет.
