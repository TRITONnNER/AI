# Агент: что реализовано поверх харнесса

Веха 0 запрещала модели, планировщик, карточки и лепет — и правильно запрещала,
пока фундамента не было. Фундамент есть, и здесь описано то, что построено
поверх: настройки, ресурсы, устройства, отвечающий мир, ошибка предсказания,
модель мира, мотивация, лепет, контуры, размыкатель, файрвол, сон, экземпляры.

Всё это проверяемо офлайн и без игры: 339 тестов, около 45 секунд.

```bash
python -m pytest -q
python -m harness.cli profile --schema            # все 134 настройки таблицей
python -m harness.cli profile --schema --group Ресурсы
python -m harness.cli devices                     # что видит и чем управляет
python -m harness.cli resources                   # пределы и текущий расход
python -m harness.cli babble /tmp/b --compare-truth   # агент открывает тело
python -m harness.cli loop /tmp/l --compare-truth     # драйв → цель → пробы → тест
python -m harness.cli bench                       # кросс-доменный замер, 4 мира
python -m harness.cli describers                  # какие сервисы описания настроены
python -m harness.cli plan                        # лепет → разведка → модель → план
python -m harness.cli report /tmp/l               # показатели и самоотчёт рядом
```

---

## Ключевое решение: мир, который отвечает

Всё остальное держится на нём. Записанный корпус — это прошлое: по нему проверяется
восприятие, но не проверяется ничего, что требует ответа мира на действие. А это
половина проекта: обратимость, ошибка предсказания, лепет, граф мест, аллостаз.

`harness.corpus.world.InteractiveWorld` отвечает. В нём есть движение, поворот,
переключаемый свет, необратимая поломка и молчащие выходы. Соответствие
«выход → эффект» выводится из сида и лежит **только** в отладочном потоке:
ни агент, ни проверяемый код его не видят.

Правил, целей, счёта, врагов и наград в мире нет. Он просто реагирует.

## Настройки: 134 ручки, каждая объявлена

`harness.core.settings` — 134 настройки, по строке на каждую: ключ, тип, **единица
измерения**, значение по умолчанию, группа, `parameter` или `structural`,
границы, пояснение. `Profile` собирается из схемы и проверяется по ней.

18 групп: Захват, Звук, Устройства, Ресурсы, Хранение, Контуры, Восприятие,
Себя и мира, Граф мест, Предсказание, Планирование, Драйвы, Осторожность, Лепет,
Сон, Файрвол, Экземпляры, Отладка.

Что даёт схема, чего не даёт словарь:

- **Единицы обязательны.** Не «длительность», а «мс». Не «память», а «МиБ».
- **Границы проверяются.** `capture_fps = -5` не доедет до записи.
- **Группа объявлена при настройке.** Ошибка «параметр, который на самом деле
  меняет форму опыта» ловится тестом, а не через месяц по несравнимым прогонам.
- **Полнота профиля обязательна.** Недостающая ручка означает захардкоженную
  константу где-то в коде, и `validate` об этом говорит.

Структурных переключателей 26 — те, что форкают журнал: формат кадра, число
каналов звука, соль символов, хеширование текста, файрвол, число экземпляров,
интернет, рандомизация мира, видимость воскрешения, влияние речи человека на
цели, режим указателя, субсумпция, эмоции, вывод звука, переключение источников
как действие, обязательная перепроверка свидетельств, предсказатель, сетка и
квантование отпечатка места, запись петель в графе мест, отладочный канал и
остальные. Точный список — `harness profile --schema`, а не этот абзац: он
генерируется, а абзац отстаёт.

Проверка деления простая: «изменится ли форма или смысл накопленного опыта, если
повернуть эту ручку на ходу?» Частота захвата не меняет — записи останутся
сравнимыми. Отключение хеширования текста меняет: агент внезапно получит
читаемый язык.

## Ресурсы: предел, который ограничивает

`harness.core.resources`. Предел, который никто не проверяет, — это комментарий,
поэтому здесь не только числа, но и то, что при упоре происходит.

| Ресурс | Мягкий порог | Упор |
|---|---|---|
| Память процесса | вытеснение рабочего контекста | отказ принимать кадры |
| Диск сессии | — | отказ принимать кадры |
| Число карточек | заявка на консолидацию | заявка на консолидацию |
| Расход на модель | — | отказ обращаться к модели |

Одно правило без исключений: **журнал не обрезается**. Инвариант 1 не знает
оговорки «кончилось место». Если места нет, запись кадров останавливается и об
этом появляется запись — но записанное остаётся целым. Обратный порядок (выкинуть
старое, чтобы записать новое) сделал бы журнал невоспроизводимым, а из него
выводится всё остальное.

Неизвестное потребление возвращается как `None`, а не как ноль: ноль означал бы
«памяти не занято» и предел бы не сработал. Измеритель подменяемый — иначе тест
на упор в четыре гигабайта требовал бы занять четыре гигабайта.

## Устройства: видеть и управлять — разные права

`harness.devices`. Различие содержательное, а не интерфейсное:

- **Погода** — видно, но не управляемо. Меняется само, предсказывать надо,
  влиять нельзя.
- **Невидимая рука** — управляемо, но не видно. Действие с невидимым
  последствием; именно на нём ломается связь действия и результата.

Ещё здесь: склейка нескольких источников в один кадр (агент получает их как одну
картинку, а переключение между ними становится **его собственным действием** и
пишется от его имени), области действия ввода с той же вложенностью, что у маски,
и бюджет задержки по звеньям.

Идентификатор источника для агента непрозрачный: `SRC_1A`, а не «Minecraft
1.21.4 — мой мир». Экранные координаты области агенту не отдаются вообще —
размер он видит из кадра, положение ему незачем.

Задержки по умолчанию нули, а не «типичные»: неизвестная задержка обязана
выглядеть неизвестной. Заполняются замером на живой машине.

## Ошибка предсказания как единая валюта

`harness.vision.predict`. Предсказатель — постоянная скорость: сдвинуть последний
кадр на тот же вектор. Это не «пока сойдёт», а осмысленный опорный уровень:
обученная модель обязана быть лучше постоянной скорости, иначе она не выучила
ничего. Считается за одно FFT, то есть годится для контура на 20 Гц.

Замер: на движущемся мире `shift` втрое точнее `copy`, всплески приходятся ровно
на смену режима движения — то есть на то, что и должно удивлять предсказатель
постоянной скорости.

Два места, где очевидная реализация была бы неверной:

1. **Всплеск определяется до обновления фона.** Иначе замкнутый круг: всплески
   раздувают дисперсию, дисперсия поднимает порог, порог перестаёт ловить
   всплески. На замере детектор молчал полностью.
2. **У разброса есть пол** (`spike_min_sigma`). Захват экрана цифровой: при
   неподвижной картинке кадры побитово одинаковы, ошибка ровно ноль и разброс
   ровно ноль — и тогда всплеск не обнаружим ни при каком пороге.

## Модель мира

`harness.model`. Всё производное: пересобирается из журнала и может быть выброшено.

**Убеждения** (`beliefs.py`). `Provenance` обязателен: без происхождения
утверждение не собирается (инвариант 7). Три происхождения различаются по
существу, а не формально: `hunch` можно выбросить, `testimony` **никогда** не
становится опытом (повторение чужого слова не есть проверка), `experience`
получено своим действием. Поэтому у убеждения два счётчика: `n` и
`n_experience`. Убеждение с большим `n` и нулевым `n_experience` — пересказ, и
его `confidence` вдвое дисконтируется.

Гипотеза без способа проверки запрещена конструктором. Гипотеза становится
убеждением только после собственной проверки — свидетельство её не подтверждает.
Собственный опыт чужим словом не переписывается, а конфликт показывается.

**Пересборка** (`rebuild.py`). На входе только журнал, на выходе убеждения и
карта тела. Проверка одна и жёсткая: два прогона дают одинаковый отпечаток.
Воображаемое (`THOUGHT`) пропускается — мысль не учит о мире.

**Граф мест** (`places.py`). Ни одной координаты. Узел знает, как он выглядит;
ребро знает, сколько секунд ходьбы туда уходило и с каким разбросом. Отпечаток
приводится к среднему яркости, поэтому «темнее» не значит «другое место» — это
проверено тестом. Маршрут — Дейкстра по измеренным временам. Потеря ориентации
считается отдельно: частая потеря означает неверный порог узнавания, и это надо
видеть, а не сглаживать. Подробности про два измеренных изъяна и их починку —
ниже, «Карта, которая исправляет себя».

**Драйвы** (`drives.py`). Шесть драйвов, аллостаз с горизонтом из профиля:
реакция на прогноз, а не на текущее отклонение. Настроение выводится из
статистики ошибки предсказания и состояния ресурсов — **ни одного слова агента о
себе** (инвариант 10).

Эмоция — не таблица «страх → горизонт три секунды». Таблица была бы
захардкоженной константой поведения и потребовала бы пятнадцати ручек. Вместо
неё непрерывная модуляция трёх порогов от валентности и возбуждения с тремя
коэффициентами из профиля. Название эмоции («досада», «скука») существует только
как ярлык для исследователя, и **тест проверяет, что ни одна ветка кода его не
читает**.

## Лепет: тело открывается с нуля

`harness.behaviour.babbling`. Главный результат этой части, и он измерен.

На пяти сидах, 1500 шагов, профиль `ЛЕПЕТ-К7`:

| Что | Результат |
|---|---|
| Живые выходы найдены | 9 из 9, ложных 0 |
| Молчащие найдены | 15 из 15 |
| Обратные пары найдены | 8 из 8, все верные |
| Необратимый выход распознан | да |
| Ложных тревог «не умею откатить» | 0 |

Агент не знает ни одного названия клавиши и ни одной функции. Он выясняет, что
одни выходы двигают мир, другие молчат, что движение вперёд откатывается
движением назад, поворот — поворотом, свет — самим собой, а сломанное не
откатывается ничем.

Четыре места, где очевидная реализация давала неверный ответ. Каждое стоит
записать, потому что все четыре — типичные:

1. **«Способ не найден» ≠ «способ не работает».** Наивный откат «нажму то же
   ещё раз» не возвращает движение, и агент считал необратимым всё, к чему не
   сразу подобрался ключ. Неудачная догадка говорит о догадке, а не о мире:
   теперь она увеличивает `undo_searches`, а обратимость остаётся неизвестной —
   то есть осторожность максимальной.
2. **Симметрия — проверяемая догадка.** Если Y вернул то, что сделал X, стоит
   проверить, вернёт ли X то, что делает Y. Это догадка, и она проверяется
   пробой, а не принимается за факт, — но проверять её надо раньше случайного
   перебора.
3. **Голодание перебора.** Выход, ломающий панели, перестаёт что-либо менять,
   когда ломать нечего. Попытки отката по нему не случаются, счётчик не растёт,
   и перебор застревает на нём навсегда: **1170 проб из 1266 уходили в один
   выход**. Лечится счётчиком подряд идущих «ничего не произошло».
4. **Вину за сочетание нельзя списывать на один выход.** Проба-сочетание жмёт
   два выхода, откат пробует один, мир не возвращается — и обратимость верно
   найденной пары падала с 1.0 до 0.33. Обратимость проверяется только у
   одиночной пробы.

## Контуры, размыкатель, файрвол

**Контуры** (`behaviour/contours.py`). Контур — генератор, а не функция: функцию
нельзя прервать, генератор отдаёт управление на каждом `yield` и сохраняет
состояние. Поэтому долгая работа планировщика нарезается без потоков и без
блокировок, а прерванный планировщик отдаёт лучшее из того, что успел. Порядок
обслуживания — от нижнего контура к верхнему: это и есть субсумпция.

Есть предохранитель на число шагов в срез. Разрешение часов может быть грубее
среза, и тогда дедлайн не срабатывает вообще, а верхний контур съедает весь шаг
вместе с рефлексами — это ровно то, что случилось в тесте с фиксированными часами.

**Размыкатель** (`behaviour/imagination.py`). Один цикл, одна переменная.
Действие, воображение, воспоминание и контрфактика — четыре режима одного
механизма. Воображаемое пишется записью `THOUGHT`, а не `ACTION`: иначе из
журнала не отличить сделанное от продуманного. `GuardedEffectors` не даёт
воображению дотянуться до мира — попытка кончается исключением, а не тихим
нажатием, потому что «не вызывать эффекторы при разомкнутом размыкателе» —
договорённость, а договорённости ломаются.

**Файрвол** (`perception/firewall.py`) — тот прибор, которого не хватало в
пульте. Вопрос «что я вижу» — константа в коде, не шаблон. Сырой запрос и сырой
ответ пишутся в отладочный поток до всякой проверки. Ответ проверяется на
императивы и оценки: нашлось — `FirewallViolation`, и восприятие не доходит до
агента вообще. Не «предупреждение в логе».

Проверено, что «Лучше атаковать врага первым» перехватывается, «это важный
предмет» перехватывается как оценка, а чистое описание проходит. В журнал уходят
только символы, зоны (девять грубых зон, не пиксели) и размеры.

Клиента большой модели нет: подключить её здесь нечем, а непроверенный клиент в
этом месте опаснее отсутствующего — он создал бы видимость работающего файрвола.
Описатель передаётся снаружи; в тестах это локальный описатель без модели.

## Цели: из давления драйвов, с тестом и бюджетом

`harness.behaviour.goals`. Награды нет — валюта одна, ошибка предсказания. Цель
не «даёт» ничего: она либо проходит свой тест, либо от неё отказываются по
бюджету. Тест проверяет это отдельно, по именам в коде: поле или функция со
словом `reward`, `score`, `utility` означала бы вторую валюту рядом с первой, и
тогда непонятно, какая главная.

Четыре правила, каждое проверяемое:

- **Цель без теста не цель.** Тест — объективная проверка: «обратимость этого
  выхода стала известна», «я в этом месте», «ошибка опустилась ниже порога».
  «Стало лучше» невыразимо, потому что «лучше» надо откуда-то взять.
- **Бюджет в собственных циклах агента**, не в секундах стены: мерить его
  терпение чужими часами неверно. Кончился — отказ, и отказ пишется в журнал с
  причиной. Отсюда же метрика «время до отказа от цели» из пульта.
- **Цель знает, откуда взялась** — тот же `Provenance`, что у убеждений. Цель с
  происхождением `testimony` конструктор не собирает: пришедшая снаружи цель
  обязана быть помечена как вмешательство.
- **Давление выбирает, но не назначает.** Кандидаты берутся из того, что
  известно: непробованные выходы, неизвестная обратимость, чужие слова без
  проверки, давно не посещённые места. Драйв не может потребовать того, о чём
  агент не знает.

Замер на прогоне 40 раундов: 9 целей, 6 прошли тест, 2 брошены по бюджету, до
успеха 1.8 такта в среднем, до отказа 10. И это осмысленно: сначала закрываются
дешёвые цели («узнать, что делает этот выход»), а потом остаётся невозможная —
найти откат для необратимого выхода, — и она честно бросается по бюджету.

## Самоотчёт: агент говорит о себе, и это ни на что не влияет

`harness.behaviour.selfreport`. Из замысла: агент должен «отдавать отчёт своим
действиям». Оттуда же — предупреждение, которое важнее самой возможности:
самоотчёты ни на что не влияют автоматически, реакция только на поведение и
объективные величины (инвариант 10).

До этого модуля инвариант 10 проверял отсутствующую вещь. Самоотчётов не было, и
тесты смотрели на то, что пометки исследователя не меняют профиля. Теперь есть чему
испортить эксперимент, и проверяется оно.

**Отчёт — набор строк с закрытым набором кодов, а не фраза.** Кодов четырнадцать:
чем занимался, какой драйв давил, какая цель активна, что удивило, что стало опытом,
что осталось чужим словом, что осталось догадкой, чего не умею откатить, чего не
знаю, как себя чувствую, какая часть тела открыта, сколько мест известно. Фраза на
естественном языке была бы текстом, который тянет разобрать и на что-нибудь завязать;
код разобрать нечем.

**Перечень незнания — самая полезная часть.** «Чего я не знаю» показывает, куда агент
*не* смотрел, а такие места не видны ни по одному счётчику успехов: непробованные
выходы, выходы в состоянии «не знаю», доля неизвестных переходов в модели.

Невозможность влияния держится на трёх механизмах, у каждого свой тест:

1. **Отчёт — сток.** Он строится из того, что у агента уже есть, и не возвращает
   ничего, чем можно управлять.
2. **Пересборка отчёты пропускает.** Как и `THOUGHT`: запись `SELF_REPORT` не создаёт
   убеждений и не меняет карту тела. Сказать «я умею откатывать этот выход» и тем
   самым сделать его откатываемым — невозможно. Тест пересобирает один и тот же
   журнал до и после дописывания отчётов: отпечаток убеждений и карта тела совпадают.
3. **Никто его не читает.** Проверяется обходом графа импортов — тем же способом,
   которым проверяется изоляция отладочного канала.

Сильнее всех трёх — проверка по результату: два прогона круга с одним seed, в одном
агент отчитывается каждый круг, в другом молчит. Тело, цели, настроение и ошибка
совпадают до последнего числа. Разойдутся — значит где-то появилось чтение отчёта.

**Отчёт проходит проверку на непрозрачность, но не ту же, что восприятие.** На
границе восприятия допустимы только символы: там всё приходит с экрана. В отчёте
строки составные (`ENT_1C90|afford|OUT_2C@200`) и содержат слова, которых на экране
быть не может — имена драйвов, виды целей, ярлыки эмоций. Поэтому строка режется на
части, и каждая обязана быть числом, символом или словом из закрытого словаря.
Расшифрованная надпись в словарь не входит и падает громко.

## Показатели: 27 чисел из журнала, каждое с единицей и источником

`harness.model.vitals`, команда `harness report`. Причина появления прозаическая: у
каждого узла был свой `stats()`, и девять сводок — это не сводка. Ответить на вопрос
«сколько уже готово и что изменилось за час» было нельзя: у каждой свои единицы, свой
момент времени и свой набор полей.

Считается **по журналу**, а не из живых объектов в памяти — это инвариант 1. Показатель,
который можно получить только из работающего процесса, нельзя ни перепроверить, ни
сравнить с прошлым прогоном.

Что считается: сколько прожито в двух часах, целостность записи (разрывы захвата и
доля потерянных кадров), тело (попыток, доля заглушённых, доля доехавших, доля
ответивших), компетентность как доля целей, прошедших тест, время до отказа от цели,
шаги планов и доля согласия предсказания с наблюдением, сон и сколько циклов с
последней консолидации, вмешательства, мысли, отчёты, свидетельства, остановы, упоры в
ресурсы, а после пересборки — убеждения, доля чужих слов, карта тела и то, чего агент
не умеет откатывать.

**Чего в журнале нет, того нет и в сводке.** Вместо числа — пустое место с причиной.
Три такие строки: средняя ошибка предсказания (живёт в процессе, по журналу её надо
пересчитывать по кадрам — это делает `bench`, не сводка), граф мест (строится по
кадрам, отдельным видом записи не пишется) и настроение (производное, не хранится, и
намеренно не показывается числом рядом с поведением — иначе прогоны начнут сравнивать
по настроению). Посчитать ошибку «примерно по числу всплесков» было бы правдоподобным
числом вместо реального, то есть ровно тем, что запрещено правилами работы.

Показатель без источника собрать нельзя: конструктор падает. Показатель со значением
`None` без причины — тоже. Пустое место в сводке обязано быть подписано, иначе оно
читается как ноль.

`harness report` печатает две колонки: слева объективные показатели, справа слова
агента о себе. **Рядом, но не вместе** — и расхождение колонок это самое интересное в
отчёте. «Я научился» при компетентности 0.2 значит, что агент считает освоенным то,
что тестами целей не подтверждается.

## Библиотека навыков: макросы из журнала

`harness.behaviour.skills`. Навык не написан руками, а найден: `mine` читает
журнал и ищет цепочки, которые повторялись и каждый раз что-то меняли. Значит
навык нельзя «сохранить» в обход опыта, и он пересобирается с нуля, как убеждения.

Три условия, без которых это было бы самообманом:

- **Найденное в журнале — догадка, а не умение.** `is_guess` истинно, пока навык
  не применён намеренно, и надёжность вдвое дисконтируется. Считать совпадение
  умением — самый быстрый способ выучить случайность.
- **Проверка объективная.** `verify` прогоняет макрос в мире и сравнивает
  состояние до и после заданной снаружи проверкой. «Применили и вроде сработало»
  не отличается от «применили».
- **Обратимость навыка — отдельный вопрос.** Цепочка из обратимых шагов может
  быть необратима целиком, поэтому она неизвестна, пока не проверена откатом
  всей цепочки. Тест на это есть, и он же показал вещь, которую стоит знать:
  сравнивать сырые кадры для проверки «вернулось ли как было» нельзя, потому что
  интерфейс живёт своей жизнью. Сравнивать надо мировой слой — ровно за этим и
  нужно разделение себя и мира.

На прогоне лепета из 900 шагов находится 18–23 макроса длиной 2–3 шага, все
помечены догадками. Проверено, что в них не попадает ни один молчащий выход.

## Сон и экземпляры

**Сон** (`model/consolidation.py`). Пересобирает убеждения, предлагает слить
похожие карточки, забывает малоценное, считает время без сверки с реальностью.
Не выдумывает: тест проверяет, что после сна не появилось ни одной карточки,
которой нет в пересборке из журнала. При слиянии побеждает тот, у кого больше
собственного опыта, а не больше повторов — иначе пересказ побеждал бы проверку
числом.

Предупреждение «давно не было сверки с реальностью» не косметика: обучаясь во
сне, агент выучивает свою модель, а не мир.

**Экземпляры** (`instances.py`). Параллельные жизни, у каждой свой сид мира и
свой журнал. Общего опыта не существует — только свидетельства, и свидетельство
опытом не становится никогда. Свидетельства пишутся в журнал получателя: иначе
после пересборки чужие слова исчезнут, и модель перестанет объясняться журналом.
Повторный сид при включённой рандомизации запрещён: иначе открытие не отличить
от воспоминания.

## Доменная независимость: проверено, а не заявлено

`CLAUDE.md` требует: «архитектура обязана быть доменно-независимой: если решение
работает только в Minecraft, оно неправильное». Заявить это легко. Проверить —
только одним способом: сделать несколько разных миров и прогнать по ним **один и тот
же код**, без единой доменной поправки.

`harness.corpus.domains` даёт четыре мира с одним интерфейсом, и различаются они
именно тем, что ломает модули:

| Домен | Как двигается содержимое | Что этим проверяется |
|---|---|---|
| Игра | камера панорамирует в двух измерениях | базовый случай |
| Документ | прокрутка строго по вертикали, рывками | сдвиг по одной оси |
| Рабочий стол | двигаются отдельные окна | глобального сдвига нет |
| Видео | содержимое идёт само, без действий | движение есть, действия нет |

`python -m harness.cli bench` прогоняет по ним разделение слоёв, ошибку
предсказания, граф мест и лепет. Сид 3, 140 кадров, 700 проб:

| Домен | Признак | IoU | Точность | Полнота: неподвижное / меняющееся обрамление | Тело |
|---|---|---|---|---|---|
| игра | три вместе | 0.81 | 1.00 | 1.00 / 0.74 | живые и молчащие все |
| документ | три вместе | 0.66 | 0.94 | 1.00 / 0.66 | живые и молчащие все |
| рабочий стол | неподвижность | 0.75 | 1.00 | 0.80 / 0.54 | живые и молчащие все |
| видео | неподвижность | 0.42 | 1.00 | 1.00 / 0.38 | живые и молчащие все |

Шесть сидов, все четыре домена — проходят все.

### Три признака разделения слоёв, а не один

**Параллакс** требует глобального сдвига: он сравнивает «сместилось вместе с кадром»
и «не сместилось». Там, где кадр не смещается целиком, сравнивать нечего. Первый же
кросс-доменный прогон это и показал: на рабочем столе и в видео **100 % пикселей
остались нерешёнными**. Отказ честный, но бесполезный.

**Неподвижность** (`StillnessSeparator`): что не меняется, когда меняется остальное.
Обои рабочего стола, полоса управления проигрывателя, рамка панели не меняются вовсе,
а окна и содержимое меняются. Признак слабейший из трёх, и это записано в коде: он не
различает «прибито к экрану» и «стоит на месте» — неподвижный камень в неподвижной
сцене он объявит экранным слоем.

**Связь с движением камеры** (`MotionCouplingSeparator`): меняется ли пиксель тогда,
когда камера **стоит**. Этот признак закрывает то, что не берут первые два, —
анимированное обрамление, ползущее заполнение полосы. Параллаксу оно не даётся,
потому что не совпадает с собой; неподвижности — потому что меняется. А прибито к
экрану оно так же, как рамка, и по замеру это 33–63 % всего обрамления. Различие
измеримо, и разделение с большим запасом:

| Класс пикселей | Частота изменений при движении | При остановке |
|---|---|---|
| неподвижное обрамление | 0.000 | 0.000 |
| анимированное обрамление | 0.049 | 0.036 |
| мир | 0.810 | 0.000 |

Мировой пиксель при стоящей камере не меняется: меняться ему нечем. Анимированное
обрамление живёт своей жизнью и меняется одинаково, движется камера или нет.

Чего третий признак не может, и это надо говорить прямо: **мировой объект, который
движется сам** — вода, чужой персонаж, мигающая лампа в сцене — меняется и при
стоящей камере, и будет принят за анимированное обрамление. В синтетическом мире
такого нет, в настоящей игре есть. И он требует записи, в которой камера и двигалась,
и стояла: в видео и на рабочем столе он честно молчит.

### Как три признака складываются в один ответ

Не выбором одного признака на весь кадр, а **с происхождением у каждого пикселя** —
по той же причине, по которой у убеждения есть происхождение. У каждого признака своя
область применимости, и отбрасывать его ответ там, где он единственный, кто может
ответить, значит терять знание. Замер по документу: третий признак даёт точность 0.94,
но решает 47 % пикселей, а параллакс решает 62 %; выбор одного на весь кадр в любом
случае терял бы часть ответа.

Что при этом не размывается: `provenance` помнит, какой признак решил каждый пиксель,
а `disagreements` считает пиксели, где два применимых признака ответили **по-разному**.
Расхождение — не мелочь, а признак того, что один из них врёт, и оно стоит отдельной
графой в таблице (замер: 1.7–1.8 % решённых пикселей в игре и документе, 0 % там, где
применим один признак).

Порядок разрешения конфликтов — по силе признака: связь с движением, потом параллакс,
потом неподвижность. Порядок выведен из того, что каждый **способен** различить, а не
из чисел. **Голосование большинством проверено и отброшено**: на всех четырёх доменах
оно даёт ровно тот же результат, что порядок по силе, а «согласие двух из трёх»
заметно хуже (в игре IoU 0.83 → 0.70, а там, где применим один признак, оно не даёт
ответа вообще).

Порядок по силе не универсально прав, и это измерено: на конфликтах в игре третий
признак прав 815 против 10, а в документе неправ — 56 против 277. Цена фиксированного
порядка в документе: точность 0.95 → 0.94 при полноте по неподвижному обрамлению
0.67 → 1.00. Сделка названа, чтобы следующий, кто будет улучшать, знал куда смотреть.

У всех трёх признаков общий честный запрет: **где нет текстуры, пиксель не голосует**.
Гладкое небо не меняется и при движении камеры. У третьего признака запрет строже, и
он тоже добыт замером: «не изменился» говорит что-то только про пиксель, который
**мог** измениться. Пиксель в белом промежутке между строками текста при прокрутке
остаётся белым — окрестность у него текстурная, а сам он неотличим от неподвижного.
Проверяется прямо: сдвинуть предыдущий кадр на глобальный вектор и сравнить с ним же.
Без этой проверки по документу было 1004 ложных пикселя и точность 0.84.

`layer_signal` в профиле — структурный переключатель: можно потребовать один
конкретный признак, и это форкает журнал, потому что накопленное разными признаками
несравнимо.

### Что здесь измерено и что отброшено

**Размах движения решает всё.** Полнота параллакса зависит от того, насколько сдвиг
крупнее самих элементов обрамления: игра при размахе 5 px даёт IoU 0.23 и полноту
0.24, при 80 px — IoU 0.95 и полноту 0.95, точность растёт с 0.89 до 1.00. Документ
насыщается около 0.67 — прокрутка идёт по одной оси, и этого не изменить.

**Ослабление порога — отброшено.** Гипотеза: голосовать за экранный слой не только
при «пиксель не изменился», но и при «своя разность в `margin` раз меньше». Замер:
игра при размахе 9 px — точность падает с 0.98 до 0.79 без прироста полноты; при 40
px — с 1.00 до 0.84; документ не меняется вовсе. Гипотеза отвергнута, кода не
изменено.

**Меняющееся обрамление** было тем, что не находил ни один признак: полнота 0.37–0.67.
Третий признак поднял её в игре с 0.56 до 0.74, а полноту по неподвижному обрамлению —
с 0.50 до 1.00; общий IoU в игре вырос с 0.54 до 0.81, в документе с 0.62 до 0.66.
В видео и на рабочем столе третий признак неприменим (камера там не движется вовсе),
и пробел остаётся: 0.38 и 0.54.

**Однородная заливка внутри панели остаётся нерешаемой в принципе.** На однородном
участке все гипотезы дают одно и то же. Раньше на это приходилась половина
неподвижного обрамления в игре; третий признак её забрал, потому что смотрит не на
совпадение с гипотезой, а на частоту изменений, — но там, где нет ни текстуры, ни
изменений, ответа нет ни у кого, и все три признака оставляют пиксель нерешённым.

### Три поправки в истине, а не в методе

Ошибка в истине хуже ошибки в методе: метод она не портит, а числа портит незаметно.
Три такие ошибки нашлись и исправлены.

1. **Экранный слой рабочего стола — не только панель задач.** Обои прибиты к экрану
   ровно так же. Прежняя истина считала огромную неподвижную область «миром» и
   наказывала метод за правильный ответ.
2. **Окно, ни разу не двинувшееся, в этой записи прибито к экрану.** Слой определён
   системой отсчёта, а система отсчёта видна только по движению. С прежней истиной
   точность на рабочем столе была 0.81 вместо 1.00 — и вся разница приходилась на
   окна, которые за прогон не шевельнулись.
3. **Пиксель, у которого истина за прогон менялась, из подсчёта выпадает.** Голоса
   накоплены по всей записи, сверять их с маской последнего кадра нельзя.

### И одна поправка в критерии

Сначала было записано, что на рабочем столе параллакс обязан молчать. Замер по трём
сидам показал обратное: когда крупное окно едет согласованно, фазовая корреляция
находит сдвиг по этому окну, и ответ выходит **верным** (точность 1.00, IoU
0.73–0.77) — едущее окно и есть содержимое, а остальное и есть экранный слой.
Требование молчать наказывало бы за правильный ответ. Судится ответ, а не выбор
признака.

## Карта тела: четыре состояния и статистика вместо порога

Кросс-доменный замер сломал и лепет — в том смысле, в котором сломать полезно.

**Одно совпадение — не открытие.** Пока живым считался выход, ответивший хотя бы
раз, прогон давал по два-четыре ложно живых выхода в каждом домене: ровно один ответ
на 26–37 попыток. Больше всего таких в проигрывателе — там картинка меняется сама,
и фон выше.

**Обратный перекос так же вреден.** Требование «ни одного ответа» для вывода
«молчит» означает, что одно случайное совпадение навсегда оставляет выход
неопределённым: пятнадцать вечно неясных выходов из двадцати четырёх.

Поэтому у выхода теперь четыре состояния — `untried`, `live`, `silent`, `unclear`, —
и порог сравнивается не с нулём, а с тем, **сколько порог врёт сам по себе**. Доля
ложных срабатываний измеряется тем же тестом на парах кадров без действия
(`background_rate`), ожидаемое число ложных ответов — `delivered × background_rate`,
а превышение считается в сигмах биномиального разброса.

**Мера последствия сменилась, и это отдельный результат.** Доля изменившихся
пикселей насыщается: в проигрывателе на холостом ходу она уже 0.636 ± 0.009, и
перемотка добавляет к ней 0.010 — один сигма, ниже любого разумного порога. Средняя
величина изменения (`frame_energy`) на тех же данных даёт 0.0557 ± 0.0021 против
0.0698, то есть почти семь сигм. `frame_change` остался у сторожевого таймера, где
вопрос именно «сколько пикселей шевелится».

**Пол порога измерен, а не выбран.** 0.002 теряет мелкие последствия (перекраска
рамки окна — 0.0016); 0.0002 в игре ловит анимацию интерфейса и роняет распознавание
живых выходов с 9 из 9 до 2 из 9. Осталось 0.001.

**Отдельная ручка на «сколько попыток до вывода „молчит“» убрана.** Она дублировала
`babble_repeats` и разошлась с ней при первой же настройке: пробовалось два раза,
требовалось три, и вывод «молчит» стал недостижим.

### Чего нельзя требовать от агента, и как это отделено в замере

Замер отдельно считает выходы, про которые **правильного ответа на эту запись нет**:

- **Незаметные в пикселях.** Смена окна в фокусе перекрашивает рамку — 284 пикселя
  из 57 600, изменение кадра 0.0016 против порога 0.0032. Требовать такого вывода
  значит требовать не восприятия, а доступа к истине.
- **Без запаса по проявлениям.** Чтобы заключить «отвечает», нужно два обнаружения, а
  каждое может не состояться. Выход, проявившийся ровно два раза за тридцать восемь
  проб, не даёт ни одного запаса, и правильным поведением остаётся воздержаться.
- **Проводка ≠ проявление.** Выход, подключённый к «закрыть окно», после того как
  окна кончились, объективно ничего не делает. Истина замера — что выход **сделал**,
  а не к чему подключён.

Зачёт по тому, чего нельзя достроить пробами: уверенных ошибок «живой вместо
молчащего» и «молчащий вместо живого» должно быть ноль. Неполное знание достраивается
пробами, ложное — нет.

## Бесплатные сервисы за файрволом: экономия квоты, а не выбор модели

`harness.perception.describers`. Файрвол восприятия был готов, а описателя за ним не
было. Теперь есть шесть адаптеров, и порядок обхода не случаен: сначала то, у чего
нет ни квоты, ни зависимости от сети.

| Сервис | Ключ | Лимиты (август 2026, требуют перепроверки) |
|---|---|---|
| Ollama (локально) | не нужен | нет квоты; moondream, smolvlm, qwen-vl, llava |
| llama.cpp / vLLM (локально) | не нужен | нет квоты, OpenAI-совместимый API |
| Google AI Studio | `GEMINI_API_KEY` | 60/мин, 1500/сут — самая большая суточная |
| Groq | `GROQ_API_KEY` | 30/мин, очень быстрый |
| OpenRouter | `OPENROUTER_API_KEY` | 20/мин, один ключ на много бесплатных моделей |
| Mistral | `MISTRAL_API_KEY` | картинки поддержаны, лимиты в консоли |

**Дефицит здесь — не деньги, а запросы.** Поэтому вся инженерия в экономии квоты, и
её четыре части:

1. **Порог по новизне** (`AskGate`). Спрашивать, только когда мир удивил, и не чаще
   чем раз в `model_min_gap_cycles` циклов. Мера новизны — та же ошибка
   предсказания, что и везде: вторая валюта означала бы вторую систему ценностей.
2. **Кэш ответов** (`AnswerCache`) по **побитовому** отпечатку кадра. Не по
   похожести: приблизительный кэш выдал бы ответ про другой кадр, и поймать это
   почти невозможно.
3. **Уменьшение кадра и окно внимания.** Токенов у картинки тем больше, чем она
   крупнее. Уменьшение — целочисленное усреднение по блокам, а не выборка каждого
   N-го пикселя: выборка теряет мелкие надписи, а они и есть то, что мы просим
   описать.
4. **Цепочка** (`Chain`). Кончилась квота у одного — спрашиваем следующего. Кто
   ответил, пишется в отладочный поток: ответы разных моделей — разные данные.

**PNG, а не JPEG**, и кодек свой, на `zlib`: JPEG теряет данные, а именно на
побитовой одинаковости неподвижных пикселей держится и разделение слоёв, и кэш.
Отправлять модели одно, а хранить другое — верный способ получить расхождение,
которое найдётся через месяц.

**Формат ответа навязан промптом**, потому что файрвол проверяет форму: строки
`МЕТКА | зона | размер`, девять грубых зон, три размера, и прямой запрет советовать и
оценивать. Вопрос — константа: `prompt()` откажется работать, если ему подсунуть
любой другой.

**Без ключа — громкий отказ.** `probe()` говорит, какую переменную окружения
выставить; `require()` бросает `BackendUnavailable`. Молча подменить живую модель
локальной заглушкой нельзя: сравнение прогонов сразу перестанет что-либо значить.
На этой машине `harness describers` показывает «нет» по всем шести — локальные порты
не отвечают, ключей нет, — и это честный результат, а не поломка.

## Планировщик: цепочка, выбранная воображением

`harness.model.forward` и `harness.behaviour.planner`. То, чего не хватало
архитектуре: цели с тестом, навыки со статистикой и размыкатель были, а того, кто
строит из них план, — нет.

### Модель перехода

Планировать нельзя без предсказания, а предсказание должно браться из опыта, а не из
правил мира: правил агент не знает. Поэтому модель — это статистика наблюдённых
переходов **«(место, действие) → место»**, выведенная из графа мест, который сам
выведен из журнала. Ни координат, ни направлений, ни расстояний; только «отсюда этим
— туда, за столько секунд, столько раз».

Три вещи делают её моделью, а не таблицей догадок:

- **«Не знаю» — законный ответ.** `predict` возвращает `None` там, где перехода не
  наблюдали, и доля незнания видна в `stats()`. Ветка через незнание в поиске не
  строится вообще.
- **Переход вероятностный.** У предсказания есть `p` — доля переходов, закончившихся
  в этом месте, — и список остальных исходов. Планировщик перебирает **все** исходы:
  отброшенная как «не самая вероятная» ветка бывает единственной, ведущей к цели, и
  на замере из-за этого не находилось 893 маршрута из 3205.
- **Действие — это выход вместе с длительностью.** Переход ключуется полным ключом
  действия (`OUT_xx@200`), а не выходом. Это не придирка к инварианту 8: пока модель
  ключевалась выходом, планировщик жал 40 мс там, где модель училась на 200 мс, и
  первый же шаг плана уходил не туда.

### Поиск

Обход по наименьшему **измеренному** времени — по `mu_seconds` рёбер графа. Время
единственная величина в модели, которую агент действительно измерял, и потому
единственная, по которой можно упорядочить маршруты, ничего не придумав.

Осторожность со стоимостью не смешивается. Прибавить к времени «штраф за
необратимость» значило бы придумать секунды, которых никто не измерял. Поэтому поиск
идёт двумя проходами в одном генераторе: сначала маршрут без неоткатываемых шагов, и
только если такого нет — любой, помеченный `risky`.

Планировщик — генератор: мир не ставится на паузу (инвариант 3), и лучший план на
текущий момент доступен после каждого расширения.

Одна ошибка в обходе стоила замера и стоит упоминания: место запоминалось только с
лучшим временем, без длины пути. Обход по времени и предел длины из-за этого
ссорились — место, впервые достигнутое дешёвым, но длинным путём, закрывало себя для
короткого, а из длинного дальше идти уже нельзя. Цена: 307 недостижимых целей из 1741,
которые в графе были.

### План — гипотеза, пока не применён

То же правило, что у навыка. Исполнение сверяет **каждый** шаг с предсказанием, и
первое расхождение прекращает план: дальше он опирается на состояние, которого нет.
Расхождение не игнорируется и не сглаживается — оно пишется в журнал и заставляет
строить новый план по обновлённой модели (`travel`). Это та же ошибка предсказания,
что и везде: планировщик работает на общей валюте, своей у него нет (проверяется
тестом по AST).

### Главный замер: от чего зависит, дойдёт план или нет

75 планов, три сида, три способа разведки. Считалось одно: прошёл тест цели или нет.

**По слабейшему звену** — сколько раз наблюдён наименее проверенный шаг плана:

| Наблюдён | Планов | Дошли | Доля |
|---|---|---|---|
| 1 раз | 17 | 4 | **0.24** |
| 2–4 раза | 7 | 7 | 1.00 |
| 5–14 раз | 17 | 17 | 1.00 |
| 15+ раз | 34 | 34 | 1.00 |

Отсюда порог `plan_min_step_n = 2`, и он взят из замера, а не из осторожности.
Причина понятна: у перехода, увиденного один раз, доля «привело туда» равна единице
по построению — делить не на что. Такой план выглядит уверенным на 100 % и доходит в
четверти случаев.

**По длине плана — и это место, где замер оказался диагнозом, а не итогом.**

Первый замер выглядел так: 1 шаг — 23 из 23, 2 шага — 39 из 39, **3 и больше — 0 из
13**. Вывод тогда был написан такой: предел не планировщика, а отпечатка вида как
представления места. Вывод оказался наполовину неверным, и разбор этого — в отдельном
разделе ниже: одна половина причины была вообще не в представлении, а в том, что граф
молча выбрасывал самое частое наблюдение. После двух починок:

| Шагов | Планов | Дошли | Доля |
|---|---|---|---|
| 1 | 62 | 62 | 1.00 |
| 6 | 239 | 224 | **0.94** |

Восемь сидов, планы до самого далёкого достижимого места, поэтому длина упирается в
глубину поиска. Планы от трёх шагов: **224 из 239 (94 %)** против 192 из 235 (82 %) с
записью петель, но без деления мест, и против 0 из 13 в исходном замере.

### Разведка, из которой получается модель

Это не украшение планировщика, а условие его работы. Случайная разведка по
непрерывному миру даёт переходы, наблюдённые по одному разу: чтобы переход
подтвердился, надо **вернуться в то же место и нажать то же самое**, а случайная
разведка не возвращается никогда. Замер по 2000 шагов без возврата: ни одного
подтверждённого перехода из тех, что нужны, и ни одного дошедшего плана.

Возврат делается **обратной парой, найденной лепетом** — собственным знанием «чем это
откатывается», а не встроенным «назад». Порядок предпочтения: подтвердить здесь →
расширить здесь → вернуться → взять наименее пробованное. Порядок тоже стоил замера:
если возврат идёт до расширения, разведка запирается в пинг-понге между двумя местами
— на прогоне она подтвердила один переход 738 раз и не открыла ни одного нового
места.

Замер перезамерен после того, как граф начал записывать петли, — потому что прежнее
число («без возврата ни одного подтверждённого перехода») держалось на другой поломке.
Сиды 5, 7, 13, по 1200 шагов:

| Возврат | Мест | Подтверждённых исходов | Из них ведущих куда-то |
|---|---|---|---|
| нет | 80 / 200 / 171 | 16 / 105 / 69 | 8 / 72 / 33 |
| есть | 60 / 46 / 59 | 82 / 93 / 60 | 70 / 88 / 26 |

Вывод тот же, причина видна лучше: без возврата разведка расширяется — мест
втрое-вчетверо больше, — и знание размазывается по местам, куда она больше не
вернётся. Формально «переходы есть», а планировать нечем.

```bash
python -m harness.cli plan          # весь стек: лепет → разведка → модель → план
```

## Карта, которая исправляет себя

Два изъяна в графе мест, найденные замером, а не чтением кода. Оба важны не сами по
себе, а тем, как они нашлись: сначала было объяснение, потом измерение, и измерение
объяснение опровергло.

### Изъян первый: «нажал и остался» выбрасывалось

Ребро появлялось только при смене места. «Нажал и остался здесь» не записывалось
никуда — казалось, что записывать нечего.

Замер: на сиде 7 разведка сделала **1500 шагов, открыла одно место и нажала один и тот
же выход 1500 раз**. Цепочка причин целиком лежит внутри этого решения. Модель перехода
собирается из рёбер графа; если «остался» ребром не становится, то про действие,
которое никуда не ведёт, модель не знает *ничего* — не «знает, что оно бесполезно», а
не знает вообще. Дальше `choose_probe` видит место без известных действий, идёт в ветку
«здесь ничего не известно» и берёт наименее использованный выход **по модели**. Модель
пуста, значит наименее использованный всегда один и тот же. Разведка запирается.

После починки, тот же сид: **58 мест, 116 подтверждённых пар, 113 из них с одним
исходом**. На сиде 5: было 27 мест и 5 подтверждённых пар, стало 68 и 102.

Мораль не про петли. Наблюдение, которое «нечего записывать», — почти всегда самое
частое наблюдение, и молча выброшенное оно ломает не ту часть системы, где его
выбросили.

### Изъян второй: нормировка яркости — это допущение о мире

Отпечаток приводится к среднему, чтобы место оставалось собой при выключенном свете.
Это полезное допущение, но это **допущение**, и оно было захардкожено в восприятие.

Замер, по истине мира (доступной только исследователю): на сиде 5 переключатель света
давал одно и то же место при разных состояниях мира, и подтверждённый на **двенадцати**
наблюдениях переход врал на первом же шаге плана — доходили **2 плана из 36**. На сиде 3,
где переключатель света в разведку не попал, доходили 40 из 40. Одна причина, два
исхода. Отдельно проверено, что дело не в шуме узнавания: на однозначных парах
одношаговое предсказание верно **5999 раз из 6000**.

Починка — не «убрать нормировку» и не «оставить как есть», а третье: **место делится
само, когда его собственные предсказания расходятся.** Отброшенные нормировкой
величины (средний уровень и контраст) запоминаются на ребре; если у пары «место,
действие» два исхода и уровни одного не пересекаются с уровнями другого с зазором из
профиля, значит место склеило два состояния мира — и порог известен, это середина
разрыва. Та же единая валюта: ошибка предсказания правит карту, а не только внимание.

Три вещи, которых механизм не делает, и каждая проверена тестом:

- **Не делит по одному наблюдению.** Одно расхождение — шум узнавания. Отсюда
  `place_refine_min_n`.
- **Не выдумывает порог, когда делить нечем.** Если величины пересекаются, дело не в
  яркости, и место остаётся склеенным. Это половина смысла: деление «на всякий случай»
  дало бы место, разделённое ни по чему.
- **Не делит статистику склеенного узла пополам.** Рёбра делимого места выбрасываются
  целиком — они собраны про узел, которого больше нет. Разведка соберёт заново; это
  дорого и это честно.

Когда яркость не разделяет, пробуется одна ячейка сетки: бывает, что состояния
различаются не яркостью целиком, а одним углом кадра — исчезнувшей панелью, открытым
окном. У ячейки свой, более высокий порог наблюдений, и это не осторожность ради
осторожности: ячеек 64, уровней 4, и при двух наблюдениях какая-нибудь ячейка разделит
группы почти всегда — деление окажется по шуму.

Что получилось на восьми сидах:

| | Планы от трёх шагов | Провалы на первом же шаге |
|---|---|---|
| без деления | 192 из 235 (82 %) | 34 |
| с делением | 224 из 239 (**94 %**) | 11 |

По сидам виден механизм, а не средняя: сид 5 — 2 из 36 стало 34 из 40, сид 13 — 0 из 13
стало 28 из 32. На сидах 3, 7, 11, 19, 23 деление **не сработало ни разу** — и там
ничего не изменилось. Ложных делений нет, и это ровно то, что нужно проверять в
механизме, который умеет портить карту.

Идентификатор разделённого места остаётся непрозрачным: полоса входит в хеш, а не
приписывается суффиксом. `PLACE_1A2B#светлое` рассказало бы агенту, что это «то же
место, но ярче», — а он обязан выяснить это сам, по тому, что оттуда ведут другие
переходы (инвариант 4).

Место делится столько раз, сколько разных признаков его склеивают — до предела
`place_refine_max_tests` (по умолчанию три). Полоса — комбинация признаков, разряд на
каждый. Предел обязателен: каждый признак удваивает число возможных узлов на один вид,
и без него место превращается в таблицу по пикселям, а граф — в набор одноразовых
записей, по которым нельзя планировать.

Замер честнее, чем хотелось бы: на интерактивном мире второй признак **не понадобился
ни разу**, и числа при одном пределе и при трёх совпадают до плана. Возможность есть,
она проверена на синтетике, где двух признаков требует само устройство мира, — но
утверждать, что она что-то улучшила здесь, нельзя.

Зато попытка её замерить нашла настоящий изъян. Полоса ключевалась пришедшим
отпечатком, а не отпечатком основы, поэтому каждый ракурс места — а их у основы до
шестнадцати — заводил свою полосу. Два вида, отличающиеся одной ячейкой из 64
(похожесть 0.98, заведомо одно место), после первого деления расходились в разные
полосы, и расхождение предсказаний между ними становилось невидимым: второе деление
не срабатывало никогда. Теперь полоса ключуется основой.

### Что такое оставшиеся 6 %

Их разобрали по одному. Из 19 провалов на восьми сидах:

- **8 — первое удивление.** Место, куда привело действие, модель раньше не видела
  вообще; знать его она не могла. Это не дефект, а ровно тот сигнал, из которого
  карта потом делится. Убрать его можно только запретив агенту встречать новое.
- **11 — честный проигрыш вероятности.** У пары уже было два исхода, план поставил
  на более частый и не угадал. Разделить их не удалось ни яркостью, ни ячейкой:
  из места, где стоит агент, эти два состояния мира неразличимы. План несёт свою `p`
  с собой, и `travel` для этого и существует.

И это видно по числам: одна попытка `execute` доводит 224 плана из 239 (94 %), а
`travel`, который перепланирует после расхождения, — **238 из 239**. Два оставшихся
провала на весь замер — «плана нет из этого места», а не неверное предсказание.

И одно наблюдение, которое стоит держать в голове при чтении замеров: **провалы
кучкуются на планах в два шага** (0 из 4 на картинке, 0 из 13 в первом замере), а
планы в один и в шесть шагов доходят. Это не странность длины. Цель здесь — самое
далёкое достижимое место, поэтому план получается коротким ровно там, где модель
дальше двух шагов ничего не знает, — то есть в склеенной области. Длина плана здесь
не причина, а симптом.

## Слои взгляда: система отсчёта × дальность

Из замысла: «нужно делать послойно — прямо перед лицом (условно интерфейс), передний
план, средний, задний», и там же «мы отказываемся от координат, ведь человек их не
использует, а оценка многих вещей происходит временем».

Слоёв получается **два измерения**, а не одно, и это уточнение экономит месяц:

- **система отсчёта** — прибито к экрану или к миру. Это `selfworld`, и интерфейс тут
  не «самое близкое»: он вообще в другой системе отсчёта.
- **дальность** — насколько сильно пиксель смещается по сравнению со всем кадром.

### Тау: время до контакта вместо расстояния — работает

Дэвид Ли: животные при прыжке и посадке используют не расстояние, а тау — «размер,
делённый на скорость роста размера». Олуша складывает крылья при фиксированном тау, а
не на фиксированной высоте.

Реализовано и замерено (`vision/layers.TimeToContact`, мир `corpus/depth.py`):

| Доля кадра, считаемая контактом | Оценок | Медианная относительная ошибка |
|---|---|---|
| 0.1 | 42 | **4 %** |
| 0.2 | 48 | **3 %** |
| 0.3 | 52 | **3 %** |

Ни расстояния, ни размера предмета, ни скорости — только скорость расширения на
картинке. Скорость роста измеряется как 1.056–1.068 при истинных 1.06.

Два места, где это чуть не оказалось самообманом, и оба стоили замера:

1. **Размер мерился по всему кадру.** Первая версия считала все яркие пиксели и давала
   120 px при истинных 6: она мерила текстуру фона. Теперь размер — связная область от
   центра внимания, то есть то, что человек и назвал бы «этот предмет».
2. **Мир и агент считали контакт по-разному.** Мир — «диаметр достиг такого-то», агент
   — «предмет занял такую-то долю кадра». Расхождение определений давало 96 %
   относительной ошибки почти целиком из ничего. Теперь определение одно с обеих
   сторон: контакт — это когда предмет заполнил поле зрения настолько.

### Частоты слоёв и фовеация — работают

«Дальний слой не надо обновлять двадцать раз в секунду — горы никуда не денутся».
`LayerClock` берёт частоты из профиля и говорит, чему пора обновиться. Замер за 300
кадров при 30 Гц захвата: экранный слой 300 обновлений, ближний 200, средний 20,
дальний 2 — **56 % обновлений не сделано**.

Фовеация (`look`): высокое разрешение в окнах внимания, огрублённая периферия — то же,
что делает глаз, и по той же причине. Замер:

| Окон | Огрубление | Детали сохранены | Элементов от полного кадра |
|---|---|---|---|
| 1 | 4 | 7 % кадра | **0.13** |
| 2 | 4 | 13 % кадра | 0.18 |
| 4 | 4 | 25 % кадра | 0.30 |

Периферия огрубляется усреднением по блокам, а не выбрасыванием пикселей: выбрасывание
теряет мелкое, а мелкое в периферии как раз и служит поводом перевести туда внимание.

### Дальность: пять попыток, из которых последние три — про измерение

Признак правильный: при движении камеры ближнее уезжает дальше, чем дальнее. Для
проверки сделан мир с настоящей глубиной — три плана с параллаксом 2.4 / 1.0 / 0.15
(`corpus/depth.py`); без него проверять было бы нечего, потому что в основном
синтетическом мире одна плоская текстура и все мировые пиксели смещаются одинаково.

Первые четыре попытки держались на фазовой корреляции и дали одно и то же: верным
находился только средний план — тот, который совпал с найденным сдвигом кадра, то есть
ответ «всё сместилось как весь кадр». Вывод был написан такой: нужен настоящий
оптический поток, это отдельная работа.

**Оптический поток появился, и выяснилось, что дело было наполовину не в методе.**
Текстура планов состояла из блоков одного размера, а на такой текстуре ни один
иерархический метод не может найти большое смещение — не «работает плохо», а не может.
Пирамида начинает с грубого уровня, чтобы поймать смещение целиком; блоки одного
размера при уменьшении усредняются в ровное поле. Замер на сдвиге ровно 34 px, вне мира:

| Текстура | Найденное смещение (ждём 34) |
|---|---|
| один масштаб, блоки 6 px | −2.4 |
| четыре октавы, равные веса | +34.0 |
| четыре октавы, веса как у естественных изображений | +34.0 |

Мир получил многомасштабную текстуру, и только после этого сравнение методов стало
сравнением методов, а не проверкой вырожденности мира. Это вторая поправка в мире того
же рода, что первая (разрежённая сыпь → крупные связные планы), и оба раза правкой
оказывался мир, а не метод.

Третья попытка — **опора на своё усилие**. Прежние методы нормировали смещение пикселя
на движение, найденное в самой картинке; у этого встроенный изъян — найденное движение
принадлежит плану, который занимает больше пикселей, и относительно него все остальные
выглядят «примерно как весь кадр». Но агент знает, **что сам сделал**: на сколько дёрнул
мышь, сколько держал клавишу. Это его тело, а не знание о мире, и никакого инварианта
не нарушает. Величина нужна только с точностью до множителя.

### Что в итоге измерено, и почему это про измерение, а не про дальность

Итог этого раздела переписывался трижды, и первые две формулировки были неверны — обе
потому, что делались по одному прогону. Сначала «дальность не находится», потом «дальний
план найден впервые, 0.55», потом «все методы на уровне случайного, 0.38».

Замер, который можно называть замером: **25 прогонов на метод** (5 сидов × 5 длин
прогона). Баланс — средняя доля верно отнесённых пикселей по трём планам; случайное
угадывание при трёх классах даёт 0.33.

| Метод | Среднее | Мин | Макс | σ | Секунд на 25 прогонов |
|---|---|---|---|---|---|
| фазовая корреляция по гипотезам | 0.49 | 0.25 | 0.83 | 0.16 | 13 |
| плотный поток DIS | 0.50 | 0.30 | 0.73 | 0.14 | 5 |
| поиск с опорой на своё усилие | 0.54 | 0.27 | 0.82 | 0.20 | 86 |

Четыре вывода, и только четвёртый — про дальность:

1. **Одиночный прогон не значит ничего.** От 0.25 до 0.83 у одного и того же метода.
   Отдельные прогоны падают ниже случайного угадывания. Три неверных вывода подряд
   получились именно так.
2. **Разница между методами меньше разброса.** Стандартная ошибка среднего при 25
   прогонах — 0.03–0.04, значит 0.54 против 0.49 — чуть больше одной ошибки. Сказать,
   что какой-то метод лучше, нельзя.
3. **Цена различается на порядок**, и это единственное различие, которое можно
   утверждать: поток в 17 раз дешевле перебора. Поэтому он и стоит по умолчанию —
   не потому, что лучше.
4. **Дальность находится частично**: 0.49–0.54 против случайного 0.33. Это не ноль и
   не работающая дальность.

Причина разброса измерена: планы перекрывают друг друга на мелком масштабе, и окно
вокруг пикселя часто захватывает два движения. Какое победит, зависит от случайностей
текстуры в этом месте, поэтому по пикселям ответ и скачет. Отдельная странность,
которую пока объяснить нечем: точность сильно зависит от длины прогона немонотонно —
длины 20 и 25 кадров дают заметно хуже, чем 15 и 30, хотя медиана по кадрам должна была
бы сглаживать.

Нужна совместная оценка «где какой слой» и «как он движется» — послойное разделение
движения. Ни один из трёх методов её не делает, и `trustworthy` у всех трёх остаётся
`False`: опираться на величину с таким разбросом нельзя, а скрывать разброс — тем более.

OpenCV — единственная тяжёлая зависимость в проекте, поэтому она в отдельном extras
(`harness[flow]`), а её отсутствие даёт **громкий отказ** `FlowUnavailable`. Тихий откат
здесь опаснее отсутствия дальности: замер показал бы числа, а по числам было бы не
видно, что считал не тот метод. Видно в `harness backends`.

### И один провал, который поймал встроенный сторож

Мир с глубиной добавлен в кросс-доменный замер, и разделение слоёв на нём
проваливается: точность 0.18. Причина названа: метод стоит на допущении «у мира одно
движение» — пиксель либо сместился как весь кадр, либо не сместился вовсе. При трёх
планах оба крайних случая ложны.

Показал это тот самый счётчик расхождений между признаками, который был добавлен
раньше «на всякий случай»: **91 % решённых пикселей, где признаки отвечают
по-разному**. В четырёх остальных доменах расхождений 0–1.8 %. Провал объявлен в
`benchmark.KNOWN_FAILURES` с причиной, остаётся красным в таблице и отличается от
неожиданного — иначе пришлось бы либо выкинуть домен и потерять знание о стене, либо
смириться с вечно красным замером и перестать замечать настоящие поломки.

## Чего по-прежнему нет

- **Настоящей большой модели за файрволом.** Адаптеры к шести бесплатным сервисам
  есть и проверены тестами, но на этой машине ни один не настроен: локальные узлы не
  запущены, ключей нет. Поэтому проверено всё, кроме самого ответа модели — формат
  промпта, экономия квоты, кэш, цепочка, отказ без ключа. Что модель ответит
  на настоящем кадре, не проверял никто.
- **Обученных сетей.** Ни весов, ни обучения: предсказатель аналитический.
  `weights/` из архитектуры пуст.
- **Дальности (ближний/средний/дальний план).** Четыре измеренные попытки, верным
  находится только план, совпавший с найденным сдвигом. Нужен настоящий оптический
  поток; таблица замеров — выше.
- **Разделения слоёв в мире с глубиной.** Метод предполагает одно движение мира; при
  трёх планах признаки расходятся на 91 % пикселей. Провал объявлен в замере.
- **Разделения слоёв там, где камера вообще не движется.** Третий признак закрыл
  анимированное обрамление в игре и документе, но требует записи с движением и
  остановками. В видео и на рабочем столе остаётся только слабейший признак, и
  меняющееся обрамление там находится на 0.38 и 0.54.
- **Различения «анимированное обрамление» и «мировой объект, который движется сам».**
  Третий признак их путает по построению. В синтетическом мире таких объектов нет, в
  настоящей игре есть — вода, чужие персонажи, мигающий свет.
- **Оставшихся 6 % планов.** Планы от трёх шагов доходят 224 из 239 на восьми сидах.
  Провалы — там, где расхождение предсказаний нашлось, но разделить его не удалось ни
  по яркости, ни по одной ячейке: делить нечем, и выдумывать порог нельзя.
- **Второго деления одного места.** Место делится один раз: `splits` держит один порог
  на место. Состояние мира, различимое двумя признаками сразу, разделится только по
  первому.
- **Плана из навыков, а не из отдельных нажатий.** Библиотека навыков есть, модель
  перехода есть, но переходы ключуются одиночными действиями. Навык как один шаг
  плана — следующий шаг, и он требует статистики переходов по навыкам.
- **Живой машины.** Захват, инъекция, звук и горячая клавиша СТОПа остаются
  непроверенными — см. `ARCHITECTURE-HARNESS.md`, «Что не проверено».
- **Видеокодека.** Предел шардового хранилища измерен: 106 ГиБ в час при 1080p с
  непрерывным движением.

## Что делать следующим

1. Второе деление одного места и деление по признаку, которого нет ни в яркости, ни в
   одной ячейке: это те самые оставшиеся 6 % планов, и они уже локализованы замером.
2. Навык как шаг плана: собирать статистику переходов не только по одиночным
   действиям, но и по макросам из библиотеки.
3. Первая живая запись: она проверит захват, инъекцию, звук и заодно покажет,
   насколько синтетика врала.
4. Экран корпуса записей в пульте — главный ежедневный инструмент, у которого до
   сих пор нет своего вида.
5. Видеокодек для кадров: предел шардового хранилища измерен.
