# SETUP.md — от чистой машины до первой записи

Этот файл написан для человека, который **ни разу не запускал проект и не будет читать код**. Ни одна строка здесь не требует заглядывать внутрь: всё, что надо знать, печатают сами команды.

Всего нужно шесть шагов. Если что-то не сходится — сразу в раздел [«Что пойдёт не так»](#что-пойдёт-не-так); там симптомы, а не рассуждения.

Порядок один и тот же на всех системах:

```
получить код → поставить зависимости → harness doctor → починить названное
            → harness selftest → harness record --plan
```

---

## Шаг 0. Что понадобится

- Компьютер **с экраном**. В контейнере, на сервере и по ssh без проброса графики записывать нечего — `harness doctor` это скажет прямо.
- Python 3.11 или новее.
- Полчаса времени. Игра **не нужна**: минимальный план записи обходится браузером.

Записывать сейчас можно на **Linux с X11**, **Windows** и **macOS**. На **Wayland нельзя** — почему и что делать, в разделе «Что пойдёт не так».

## Шаг 1. Получить код

Ветка называется `claude/save-claude-design-draft-ul62eo`. **Указать её обязательно:** в основной ветке (`main`) лежит только файл README, и клон без имени ветки даст пустой каталог. Это самая частая причина «у меня ничего нет».

### Если git есть

**Сначала выберите каталог, в котором можно писать.** Кладите код **внутрь своей домашней папки** — `~` на Linux и macOS, `%USERPROFILE%` на Windows. Не в `C:\Windows\System32`, не в `C:\Program Files` и **не в корень диска `C:\`**.

Про корень диска это не придирка, а измеренная ошибка. Папка, созданная в `C:\` из окна администратора, достаётся администраторам, а обычному пользователю остаётся только чтение. Клонирование туда проходит, `dir` показывает все файлы — и `py -m venv` падает с «Отказано в доступе», потому что писать в эту папку уже нельзя. Домашняя папка принадлежит вам всегда, и этой ловушки в ней нет.

**Linux, macOS:**

```bash
mkdir -p ~/ai && cd ~/ai
git clone -b claude/save-claude-design-draft-ul62eo https://github.com/TRITONnNER/AI.git harness
cd harness
ls
```

**Windows (командная строка, `cmd.exe`):**

```bat
cd /d %USERPROFILE%
mkdir ai
cd ai
git clone -b claude/save-claude-design-draft-ul62eo https://github.com/TRITONnNER/AI.git harness
cd harness
dir
```

Путь получится вида `C:\Users\ВАШЕ_ИМЯ\ai\harness`. Он и должен быть внутри `C:\Users\` — это и есть домашняя папка.

Увидите: `Cloning into 'harness'...`, несколько строк про объекты, `Resolving deltas: 100%`, затем список файлов: `CLAUDE.md  README.md  SETUP.md  src  tests  tools  docs` и ещё десяток `.md`.

Список каталога в `cmd.exe` — это `dir`. Команды `ls` там нет: она есть в PowerShell и в Unix, а в командной строке отвечает «не является внутренней или внешней командой».

Если видите только `README.md` — клон без имени ветки; удалите каталог и повторите команду целиком.

**Если уже склонировали не туда** — в `System32`, в `C:\Program Files` или в корень `C:\`, — **не переносите, а склонируйте заново** в домашнюю папку командой выше.

Перенос выглядит проще, но не работает: у папки, созданной администратором, остаются его права, и они переезжают вместе с ней. Каталог окажется на новом месте и по-прежнему закрытым на запись — с тем же «Отказано в доступе», только уже без понятной причины. Клонирование в домашнюю папку создаёт её от вашего имени, и права получаются ваши.

Старый каталог мешать не будет. Удалить его потом — из окна администратора:

```bat
rmdir /s /q C:\ai
```

## Шаг 2. Поставить зависимости

Дальше команды **различаются по системе**. Найдите свой раздел и не смотрите в остальные.

### Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install --upgrade pip
python3 -m pip install -e '.[linux,dev]'
```

Увидите: `Successfully installed harness-0.1.0 mss-... numpy-... evdev-... sounddevice-... pytest-...`.

Если `python3 -m venv` ругается на отсутствие `ensurepip` — поставьте пакет и повторите:

```bash
sudo apt install -y python3-venv
```

### macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install --upgrade pip
python3 -m pip install -e '.[macos,dev]'
```

Увидите то же `Successfully installed ...`. Если `python3` не найден:

```bash
brew install python@3.12
```

### Windows

Сначала проверьте, что Python есть:

```bat
py -V
```

Увидите `Python 3.12.x` или подобное. Если ответ «`py` не является внутренней или внешней командой» — Python не установлен:

```bat
winget install --id Python.Python.3.12 -e
```

затем **закройте и откройте окно заново** — иначе `py` не появится в PATH — и повторите `py -V`.

**Командная строка (`cmd.exe`)** — то, что открывается по `Win+R` → `cmd`:

```bat
py -m venv .venv
.venv\Scripts\activate.bat
py -m pip install --upgrade pip
py -m pip install -e ".[windows,dev]"
```

Порядок важен: `pip` обновляется **после** активации, иначе обновится не тот — системный, а не тот, что в `.venv`. Если первая строка упала, третью и четвёртую вводить бессмысленно: они уйдут в системный Python.

**PowerShell** — то, что открывается по `Win+X` → «Терминал»:

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
py -m pip install --upgrade pip
py -m pip install -e ".[windows,dev]"
```

Файл активации у них **разный**: `activate.bat` для командной строки, `Activate.ps1` для PowerShell. Если запустить не тот, окружение молча не включится, а следом `harness` не найдётся.

После активации приглашение начинается с `(.venv)` — по этому признаку видно, что сработало. Затем увидите `Successfully installed harness-0.1.0 mss-... numpy-... dxcam-... sounddevice-...`.

Если PowerShell отказывается запускать `Activate.ps1` со словами про политику выполнения:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

и повторите активацию.

## Шаг 3. `harness doctor` — что на этой машине не так

```
harness doctor
```

Команда сама определяет систему и оконный менеджер и печатает по пунктам `есть` / `НЕТ` / `не проверено`. Пример на машине без экрана:

```
Машина: Linux 6.18.5, оконная система none (ни XDG_SESSION_TYPE, ни WAYLAND_DISPLAY, ни DISPLAY)
Python: 3.11.15

Нужно для записи:
  [  есть  ] версия Python                3.11.15 (нужно 3.11+)
  [  есть  ] зависимости                  все на месте: numpy
  [  НЕТ   ] графическая сессия           нет (ни XDG_SESSION_TYPE, ни WAYLAND_DISPLAY, ни DISPLAY)
             чинить: запустите на машине с экраном; в контейнере и по ssh без проброса X захватывать нечего
  [  есть  ] свободное место              29.2 ГиБ свободно — это около 3.2 ч записи при 30 кадр/с

Понадобится позже (записи не мешает):
  [  НЕТ   ] ffmpeg                       не найден в PATH
             понадобится к третьему уровню журнала: sudo apt update && sudo apt install -y ffmpeg

ЗАПИСЫВАТЬ НЕЛЬЗЯ. Чинить первым: графическая сессия — запустите на машине с экраном
```

**Как это читать:**

- **Строка «механизм захвата» говорит, что именно выбрано и почему.** На Windows выбирается Desktop Duplication (`screen_dxcam`): он видит полноэкранные игры и держит 30 кадров при 1080p. Запасной `screen_mss` работает везде, но полноэкранные приложения через него **не захватываются**, и он даёт около 20 кадров вместо 30 — если активен он, доктор скажет об этом отдельной строкой «полноэкранные приложения».
- Два раздела не смешивать. **«Нужно для записи»** — без этого не поедет. **«Понадобится позже»** — можно не трогать: ffmpeg нужен сжатию кадров, права на устройство ввода — тому, чтобы агент нажимал сам. Записывать они не мешают.
- У каждого `НЕТ` **есть строка с командой**. Её можно скопировать целиком.
- Последняя строка — единственная, которую надо прочитать обязательно. Она говорит «можно» или «нельзя» и что чинить первым.

Повторяйте `harness doctor`, пока последняя строка не станет:

```
ЗАПИСЫВАТЬ МОЖНО. Дальше: harness selftest, затем harness record --plan
```

## Шаг 4. `harness selftest` — а записалось ли

`doctor` отвечает «можно ли». Этот отвечает «получилось ли». Разные вопросы: разрешения могут быть выданы, а кадры приходить чёрными.

```
harness selftest
```

Займёт около десяти секунд. **Пока идёт — подвигайте мышью или прокрутите окно:** одна из проверок ищет различия между кадрами, и на полностью замершем экране она справедливо ругнётся.

Увидите:

```
  [да ] кадры приходят: 300 кадров за 10.0 с
  [да ] частота не ниже заявленной: 29.8 кадр/с при заявленных 30
  [да ] кадры не чёрные: разброс яркости 61.4
  [да ] кадры не одинаковые: соседние кадры различаются
  [да ] звук пишется: 960 отсчётов, 2 канала
  [да ] каналы различаются: каналы разные
  [да ] записи журнала создаются: 300 записей
  [да ] actor_layer = human: все 300 записей от человека
  [да ] поля записей заполнены: ссылка на кадр и три часа на месте
  [да ] воспроизведение работает: первый кадр прочитан и совпал с записанным

Всё прошло. Запись лежит в /tmp/harness-selftest-.../session.
Дальше: harness record --plan
```

Команда выполняет **все** проверки, между которыми нет зависимости, и в конце печатает сводку. Останавливается она только там, где следующая проверка невозможна физически: воспроизводить нечего, пока журнал не записан.

Если что-то не сошлось, в конце будет сказано, сколько прошло и что чинить первым:

```
  [да ] кадры приходят: 300 изменившихся и 0 без изменений за 10.0 с, механизм screen_mss
  [НЕТ] частота оборотов не ниже заявленной: 19.9 оборот/с при заявленных 30
  [да ] кадры не чёрные: разброс яркости 61.4
  [да ] кадры не одинаковые: соседние кадры различаются
  ...
Прошло 8 из 9.
Чинить первым: частота оборотов не ниже заявленной.
Где именно: получено 19.9 оборот/с, порог 24.0. активен screen_mss, и он не держит
заявленной частоты: полноэкранные игры через него не захватываются... Сначала
проверьте механизм — harness doctor покажет, какой выбран и почему
```

Про **неподвижный экран** отдельно. Если вы записываете неподвижность, кадры обязаны быть одинаковыми, и «изменившихся кадров» будет почти ноль — это правильный ответ, а не поломка. Чтобы проверка это учла:

```
harness selftest --static
```

Звук записи не блокирует. Если мешает только он:

```
harness selftest --no-audio
```

## Шаг 5. `harness record --plan` — что именно записывать

```
harness record --plan
```

Печатает **минимальный** набор: пять записей, около пятнадцати минут, игра не нужна.

```
Набор «минимальный: только браузер и рабочий стол»: 5 записей.
Что нужно: ничего ставить не надо — хватит браузера.
Сколько это: около 15 минут записи.

  1. stillness   неподвижность — 60 с
     как:   запустить, ничего не нажимать и не двигать мышью
     команда: harness record ~/harness-live/stillness --actor human --seconds 60
              harness ingest ~/harness-live/stillness --corpus ~/harness-live/corpus --kind stillness
  ...
Этого набора достаточно для: первое сравнение синтетики с живым.
Игра для этого не нужна.
```

Команды в плане уже содержат **числа**, а не «N»: секунды считать не надо.

Полный набор с игрой — `harness record --plan --set full`. Он добавляет эго-движение, интерфейс и смерть, но первое число даёт уже минимальный.

### Записать первую

```
harness record ~/harness-live/stillness --actor human --kind stillness --seconds 60
```

Увидите:

```
60 с при 30 кадр/с = 1800 кадров
механизм: screen_dxcam (Desktop Duplication)
ход записи пишется в /home/оператор/harness-live/stillness-progress.log, а не на экран — вид записи «stillness»: на ней мерится отсутствие изменений экрана, и мигающая строка в терминале попала бы в кадр как изменение
смотреть на ходу: tail -f /home/оператор/harness-live/stillness-progress.log
записано за 1:00: 214 изменившихся кадров и 1586 отметок «без изменений», 41.3 МиБ (2.4 ГиБ/ч) → /home/оператор/harness-live/stillness
слой-инициатор: human, линия LIN_3F9A2B10 (своя, не контейнерная)
Дальше: harness ingest ~/harness-live/stillness --corpus ~/harness-live/corpus --kind ВИД
```

На остальных видах записи ход идёт **строкой на экране** и обновляется раз в секунду на месте:

```
0:12 из 1:00 ·   20% · кадров 300, без изменений 60 · 14.3 МиБ, 4.1 ГиБ/ч · осталось ~0:48
```

`--actor human` обязателен: он ставит в журнал отметку, что действовал человек. Без неё живая запись неотличима по атрибуции от синтетической.

`--kind` не обязателен, но от него зависит, куда идёт ход записи. На записи «неподвижность» строка в терминале сама меняет экран, а изменение экрана здесь — то, что записывается: при 30 кадр/с обновление раз в секунду делает изменившимся до 3.3 % оборотов. Поэтому там ход уходит в файл.

**Если запись надо остановить — `Ctrl+C`.** Это не поломка: запись закрывается, в журнал ложится отметка «прервано на N секундах из M», и частичная запись годна к приёму. Числа за прерванную запись печатаются те же.

Числа в примере — с чужой машины, у вас будут свои. Строку хода видно сразу, с первой секунды: если её нет, запись действительно не идёт, и это повод смотреть `harness doctor`, а не ждать.

### Принять её в корпус

```
harness ingest ~/harness-live/stillness --corpus ~/harness-live/corpus --kind stillness
```

Увидите строки `принято: ...`, число кадров, ветку и формат. Если запись доехала испорченной или сделана не тем инструментом — команда **откажется**, а не примет с оговоркой.

Дальше остальные четыре записи по тем же двум командам из плана.

### Отдать записи обратно

Каталог `~/harness-live/corpus` целиком — это всё, что нужно. Заархивируйте и передайте:

```bash
cd ~ && tar czf harness-live.tar.gz harness-live/corpus
```

На Windows проще мышью: щёлкнуть по папке правой кнопкой → «Отправить» → «Сжатая ZIP-папка». Или командой:

```bat
tar -a -c -f %USERPROFILE%\harness-live.zip -C %USERPROFILE% harness-live\corpus
```

## Что пойдёт не так

Симптом слева, причина и что делать справа. Ни один пункт не требует читать код.

### Чёрный кадр на macOS

**Симптом:** `harness selftest` печатает `кадры не чёрные: разброс яркости 0.00, максимум 0`, а `harness doctor` — `разрешение на запись экрана: не выдано или отозвано`.

**Причина:** macOS отдаёт кадр правильного размера, заполненный нулями, если приложению не разрешена запись экрана. Ошибки при этом нет — с точки зрения программы захват «удался».

**Что делать:** Системные настройки → Конфиденциальность и безопасность → Запись экрана → включить галочку у **Терминала** (или того приложения, из которого запускаете) → **закрыть и открыть терминал заново**. Без перезапуска разрешение не подхватится, и симптом останется прежним.

### Пустой захват на Wayland

**Симптом:** `harness doctor` печатает `механизм захвата: НЕТ — под wayland backend'а нет`, а `harness record` отказывается со словами про Wayland.

**Причина:** захват под Wayland идёт через PipeWire с отдельным разрешением, и такого механизма в проекте нет. Библиотека, которой пользуется проект, работает через X11: под Wayland она либо ничего не видит, либо видит только часть окон, либо отдаёт чёрный кадр. **Отказ здесь сделан нарочно:** запись через XWayland по формату не отличается от настоящей, а по содержанию мусор, и обнаружилось бы это через недели.

**Что делать:** выйти из сеанса (Выйти / Log out), на экране входа нажать шестерёнку у поля пароля, выбрать сеанс **«X11»** или **«Xorg»**, войти снова. Проверить:

```bash
echo $XDG_SESSION_TYPE
```

Должно напечатать `x11`. После этого `harness doctor` скажет `механизм захвата: есть`.

### Моно вместо стерео

**Симптом:** `harness selftest` печатает `каналы различаются: НЕТ — каналы совпадают побитово`.

**Причина:** выбран микрофон, а не петлевой вход. Микрофон пишет комнату; нужно то, что слышно из колонок. Два одинаковых канала — это моно, продублированное в два, и пеленг по нему не считается вовсе: он считается из **разницы** каналов.

**Что делать:**

- **Linux:** найти monitor-источник и передать его имя:

  ```bash
  pactl list short sources | grep monitor
  harness record ПУТЬ --actor human --seconds 60 --audio-device ИМЯ_ИЗ_СПИСКА
  ```

- **Windows:** «Звук» → «Запись» → включить **«Стерео микшер»** (Stereo Mix). Если его нет: `winget install --id VBAudio.VBCable -e`.
- **macOS:** петлевого входа нет из коробки: `brew install blackhole-2ch`, затем в «Настройка Audio-MIDI» собрать устройство с несколькими выходами.

Звук записи **не блокирует**: `harness selftest --no-audio` и обычная запись работают без него. Без звука не проверить только слух агента.

### ffmpeg не в PATH

**Симптом:** `harness doctor` печатает `ffmpeg: НЕТ — не найден в PATH`, в разделе «понадобится позже».

**Причина:** ffmpeg нужен третьему уровню журнала — сжатию кадров в видео. Записи он не мешает: без него кадры лежат кадрами и занимают больше места.

**Что делать (когда понадобится):**

- Linux: `sudo apt update && sudo apt install -y ffmpeg`
- macOS: `brew install ffmpeg`
- Windows: `winget install --id Gyan.FFmpeg -e`, затем закрыть и открыть терминал — иначе PATH не обновится.

### `«ls» не является внутренней или внешней командой`

**Причина:** это командная строка Windows (`cmd.exe`), а `ls` — команда Unix и PowerShell. Ничего не сломалось.

**Что делать:** список каталога в `cmd.exe` — `dir`. Ниже таблица того же для трёх оболочек, чтобы не искать:

| Что нужно | `cmd.exe` | PowerShell | Linux, macOS |
|---|---|---|---|
| список каталога | `dir` | `ls` или `dir` | `ls` |
| перейти в каталог на другом диске | `cd /d C:\ai` | `cd C:\ai` | `cd ~/ai` |
| активировать окружение | `.venv\Scripts\activate.bat` | `.venv\Scripts\Activate.ps1` | `source .venv/bin/activate` |
| показать переменную | `echo %PATH%` | `$env:PATH` | `echo $PATH` |

### `Отказано в доступе` при создании `.venv`, а `dir` при этом всё показывает

**Симптом:**

```
py -m venv .venv
Error: [WinError 5] Отказано в доступе: 'C:\ai\harness\.venv'
```

и следом, если продолжить:

```
error: could not create 'src\harness.egg-info': Отказано в доступе
ERROR: Failed to build ... when getting requirements to build editable
"harness" не является внутренней или внешней командой
```

**Причина:** каталог лежит вне домашней папки — обычно в корне `C:\` — и создан из окна администратора. Читать его можно, поэтому `dir` показывает все файлы и кажется, что всё в порядке. Писать нельзя, поэтому не создаётся ни `.venv`, ни служебный каталог `src\harness.egg-info`. Команда `harness` после этого не появляется просто потому, что установка не дошла до конца.

Три сообщения об одной причине, и это сбивает: чинить надо первое, остальные пройдут сами.

**Что делать:** склонировать заново в домашнюю папку. Не переносить — права переедут вместе с каталогом:

```bat
cd /d %USERPROFILE%
mkdir ai
cd ai
git clone -b claude/save-claude-design-draft-ul62eo https://github.com/TRITONnNER/AI.git harness
cd harness
py -m venv .venv
```

Если `Отказано в доступе` повторилось **и в домашней папке** — дело не в правах каталога. Тогда смотрите «Контролируемый доступ к папкам» в Защитнике Windows (Безопасность Windows → Защита от вирусов и угроз → Управление защитой от программ-шантажистов) или добавьте каталог в исключения антивируса.

### Всё требует прав администратора, установка падает на правах

**Симптом:** `pip install` пишет `Access is denied` или `Permission denied`, `py -m venv` не создаёт каталог.

**Причина:** код лежит в системном каталоге — `C:\Windows\System32`, `C:\Program Files` или похожем. Клонировать туда получается, если окно запущено от администратора, но питоновское окружение там работать не будет.

**Что делать:** перенести каталог и работать в обычном окне:

```bat
move C:\Windows\System32\harness C:\ai\harness
```

затем `Win+R` → `cmd` → `cd /d C:\ai\harness` и с шага 2 заново.

### `Permission denied: ...\python.exe` при повторном `py -m venv .venv`

**Симптом:** окружение уже создано и активно, `py -m venv .venv` повторяется и падает на `python.exe`.

**Причина:** пересоздать окружение поверх работающего нельзя — его собственный `python.exe` в это время запущен. Ничего чинить не нужно: окружение уже есть.

**Что делать:** ничего. Признак, что оно активно, — приглашение начинается с `(.venv)`. Если начинается — переходите к следующему шагу. Если нет — активируйте, не создавая заново:

```bat
.venv\Scripts\activate.bat
```

Пересоздавать нужно только если окружение испорчено, и тогда его сначала удаляют:

```bat
deactivate
rmdir /s /q .venv
py -m venv .venv
```

### `harness: command not found`

На Windows дословно: `"harness" не является внутренней или внешней командой, исполняемой программой или пакетным файлом`.

**Причина одна из двух, и различить их просто:**

1. **Окружение не активировано** в этом терминале. Оно активируется заново в каждом новом окне. Признак: в приглашении нет `(.venv)`.
2. **Установка не прошла.** Признак: `(.venv)` в приглашении есть, а команда всё равно не находится. Тогда смотрите, чем закончился `pip install -e` — если там `Отказано в доступе`, дело в каталоге (пункт выше), а не в команде.

**Что делать:** активировать окружение — командой для **своей** оболочки:

- Linux, macOS: `source .venv/bin/activate`
- Windows, командная строка (`cmd.exe`): `.venv\Scripts\activate.bat`
- Windows, PowerShell: `.venv\Scripts\Activate.ps1`

Признак, что сработало: в начале строки приглашения появится `(.venv)`. Файл не тот — окружение не включится молча.

Если и после этого не находит — запускайте через модуль, это то же самое:

```bash
python3 -m harness.cli doctor
```

**Причина:** клонировали без имени ветки. В `main` лежит только README.

**Что делать:** удалить каталог и повторить команду из шага 1 **целиком**, вместе с `-b claude/save-claude-design-draft-ul62eo`.

### `не пуст`

**Причина:** по этому пути уже есть запись. Записи не дописываются поверх других — иначе две записи смешались бы в одну, и разделить их потом нечем.

**Что делать:** ничего придумывать не нужно — команда сама говорит, что там лежит и какой командой писать следующую:

```
~/harness-live/stillness: здесь уже лежит сессия, 641 записей, прервана: прервано на 12 с из 60 с (214 кадров, 427 без изменений).
Сессии не дописываются поверх: журнал только дозаписывается внутри своей линии, а вторая запись — это другая линия.
Эта запись годна к приёму: harness ingest ~/harness-live/stillness --corpus ~/harness-live/corpus --kind ВИД
Писать следующую: harness record ~/harness-live/stillness-2 --seconds 60
```

Прерванная запись — годная запись, просто короче задуманной: её можно принять в корпус, и `harness verify` на неё не жалуется.

### Мало кадров в секунду

**Симптом:** `частота не ниже заявленной: НЕТ — получено 12.4 кадр/с, порог 24.0`.

**Причина:** захват не успевает: экран большой, машина занята.

**Что делать:** закрыть тяжёлые окна и повторить. Если повторяется — записывайте как есть и скажите об этом: запись с меньшей частотой пригодна, а вот запись, притворяющаяся тридцатью кадрами при двенадцати, — нет.

## Что происходит с записями дальше

Это можно не читать — на всякий случай, чтобы было понятно, зачем всё.

Записи оператора **не смешиваются** с синтетическими в замерах, и это главное. Все числа проекта пока получены на мирах, которые писались вместе с проверяемым кодом: детектор разделения себя и мира показывал IoU 0.97 на такой синтетике и 0.18 на мире, написанном позже и независимо. Пока нет живой записи, любое такое число — согласие кода с самим собой.

Ожидание записано заранее: на живом экране IoU около 0.6. Если окажется сильно ниже — переделывать придётся то, что на нём стоит, и лучше узнать это сейчас, чем после того, как поверх будет построено ещё две вехи.

Одна вещь, которую можно сделать сверх плана и которая сильно помогает: отметить на любой записи прямоугольник интерфейса (полоски, счётчики — всё, что не мир):

```
harness mark ~/harness-live/corpus/stillness-stillness --screen ВЕРХ ЛЕВО ВЫСОТА ШИРИНА
```

Числа — в пикселях, на глаз, грубо. Без этой разметки IoU на живой записи не считается вовсе: сравнивать ответ метода не с чем.
